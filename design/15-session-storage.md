# 15 - 会话条目存储与无副作用重放

本文是 core 存储信封、原子重放、异步保存与冷恢复审计的唯一权威源；Studio 双库划分与
启动恢复见 [17](./17-studio-storage.md)，core 内核契约见 [16](./16-core-contracts.md)。

## 15.1 通用存储信封

通用会话条目（SessionEntry）是独立于产品协议的存储信封，包含 owner/Turn 归属、ID、顺序、
revision、时间、格式与版本。payload 保留原始 UTF-8 字符串，不要求 JSON；空白、大数字、
Unicode 和 NUL 不得被规范化。格式不授予控制权限，保留记录身份由框架分配；记录来源由
core 分配的保留 ID 区分，不能从载荷 format 推断框架类型——上层格式可以使用任意非空命名
空间，未知载荷的保存、删除和恢复不按 format 前缀过滤。

提交（SessionEntryCommit）保存有序 Put/Delete，替换和删除保留旧版本。重放状态先验证整个
批次，再原子推进状态和水位；归属、序号或删除目标无效时保留之前的完整完整状态，调用方可
以保留有效水位继续诊断或重新读取，不执行任何模型或工具副作用。通用重放在默认纯内存构建
可用，不调用业务 decoder、模型、工具或当前配置。

## 15.2 SQLite 后端

显式启用 core 的 sqlite feature 后可创建 SQLite 会话存储；默认不链接 ORM 和文件锁。资源
注册接收不透明载荷并保存不可变资源：同 ID 同内容幂等，不同内容报冲突；元数据默认上限
1 MiB，已提交 Thread journal 不套用该限制，而由队列压力约束下一次执行准入。

Thread journal 以框架保留资源 ID 保存已冻结编码，完整业务 payload、模型上下文、调用关联
和状态同 commit。后端仅解码通用外层信封与 journal，不解释工具或产品正文，不按业务类型
建表。journal 读取校验 owner、序号键和日志顺序；产品通过日志自行投影历史及交互。SQLite
的具体 ORM 错误只在后端内部构造与转换，对外以标准错误链承载，不重导出 ORM 类型。

writer 在内存保存受理水位、待保存字节、错误与关闭状态，异步事务批量写入。单资源 flush
显式接收 Thread ID 和已受理 commit 序号：SQLite 将该不可变记录映射到 writer 的受理水位，
等待该记录而非刷新瞬间的全局尾部；已持久化记录不受其他 Thread 的新增队列或失败影响。
全局 flush 捕获调用时尾部。压力、错误与恢复对 Thread 可观察；失败不丢弃排队事实。压力
快照同时报告后台 writer 错误，Thread 在模型准入前检查并保留类型化错误源；flush 重试成功
才解除失败状态。初始化失败显式关闭探测连接；shutdown 排空、join 并关闭共享连接池后才
释放数据库文件锁。模型步骤在准备开始和请求实际准入前分别检查共享冷存储压力/错误与关闭
门禁：准备期间其他 Thread 推高 writer 压力时，不启动该 prepared call，也不消费本轮输入和
消息。

Thread commit 在首次发布时冻结一次冷编码，后续保存受理重试只复用相同编码；错误源编码为
可查看的错误链，恢复诊断不实例化 provider 或插件异常类型；缺少工具业务解码器不影响提交
记录加载。已提交的 Thread 冷记录不套用普通资源元数据的单条 1 MiB 限制——已成立的事实
必须进入 writer，新的执行受理由待保存字节阈值暂停，不能丢弃当前提交来满足阈值。

## 15.3 异步保存与背压

热状态先提交，writer 异步追写；默认最多五秒或 64 条触发，flush 固定调用时水位。默认每
Thread 64 MiB、每 store 256 MiB 待保存量暂停新的执行受理，32 MiB/128 MiB 提示压力并作为
恢复水位；低于一半后恢复。取消、查询、交互收束、保存重试和关闭仍能提交。已受理任务保留
真实结果，因此受理阈值不是进程内存硬上限，已完成结果不得因超限丢失。

## 15.4 冷恢复与纯重放

历史重放只应用已保存事实，不调用模型或工具，也不运行业务 decoder 或当前渲染器。Thread
恢复先纯重放已保存 commit，再产生恢复收束提交：遗留 Running 尝试/任务/Turn 标记
Interrupted，未配对工具调用写入明确的中断结果，不执行工具或模型。恢复接收新模型实例，
清空旧私有接续和工具注册；历史载荷及旧终态保留，新执行须由宿主重新装配。恢复入口同时
验证外层存储归属、序号键和提交归属。

重放校验 Thread 归属、连续提交序号和记录信封，应用追加/替换/删除。Thread 日志重放进一步
验证通用执行不变量：请求从 Running 单向转为终态，原 turn/attempt/input revision/冻结工具
声明不能被终态记录改写；模型已提交输出必须匹配请求身份；上下文的调用信封可暂时存在待
交付调用，但不能存在孤立或重复结果。

Studio 从同一日志水位投影 Item、Turn、Interaction 和业务面板。未知格式可查看原始载荷；
无法解释的上层历史内容投影为统一原始记录：保留每段 format、version 与原始字符串，界面
以可选择的纯文本展示，不通过 Markdown 或 JSON 重新渲染原文。显示未知记录不授权继续执行；
继续执行必需的格式无法解释时明确失败，不默认为空状态。物理资源引用必须具备可验证的
内容保存责任，仅保存路径不能保证重放。

## 15.5 关闭语义

关闭封闭准入并中断当前代次，保存真实在途结果、取消待答交互，等待模型和工具关闭，再保存
最终 commit。挂接冷存储的 Thread 关闭先提交资源终态，再 flush 该终态；对外只有 durable
水位覆盖关闭 commit 才显示 Closed，等待保存或保存失败时仍显示 Closing，并保留 owner、日志
和重试入口；重复关闭不重新释放已确认关闭的模型或工具。保存失败显示 Closing 并保留
owner。共享 SQLite store 在全部 Thread 关闭后排空 writer、join、关闭连接池，再释放数据库
文件锁。

## 15.6 格式演进

会话库 schema 版本与 Thread commit 冷编码格式版本以代码常量为准，冷编码是版本化不透明
信封，嵌套模型/工具 payload 保留各自 format/version/content。core 打开不兼容库返回类型化
的不支持错误并保留字节，不自动重置，也不在正常读写路径双读旧版本。Studio 按
[17](./17-studio-storage.md) 协调升级；各格式所有者提供迁移转换，core 只负责自身通用格式，
不解码产品或 provider 内容。迁移完成后交给当前存储和重放入口。

Turn 正常结束统一为 Completed；工具结束来源保留在原始工具事实中。格式升级将历史
ToolCompleted 转换为 Completed，旧完成、进度和通知载荷在 Studio 迁移边界转换，不恢复旧执行入口。
