# 16 - Core 内核契约

本文定义 pl-core 的载荷、上下文、模型调用、扩展 CAS、交互解析与各域能力归属等内核契约。
crate 依赖方向见 [02](./02-crates.md)；状态与历史存储见 [15](./15-session-storage.md)；Studio 宿主
行为见 [14](./14-runtime-host.md)。

## 16.1 所有权总则

pl-core 拥有 Thread、Turn、模型和工具调用契约、通用上下文、交互、任务、消息、当前状态
checkpoint 与不可变 effect；
model 和 tool 实现核心接口且不相互依赖；trace 只读消费核心观察接口。pl-studio-runtime 拥有
配置持久化、项目、Profile、Mode/workflow/Plan、子代理协调和唯一装配入口，root、child 和
冷恢复使用同一装配路径。core 不提供默认工具、Git、Skill 或 Profile 自动安装入口：pl-tool
的工具组只构造工具，Studio 显式注册并单独加入业务 plan/workflow 工具。文件、容器、Skill
工具、exec、命令任务管理与 SSH 客户端归 pl-tool；宿主进程创建策略的唯一实现归
pl-remote-helper；bridge 经 Studio 的 SSH 接口类型映射，不直接组合工具运行时。每个 Thread
独占工具管理器、工具实例及模型会话；物理服务按身份与隔离边界通过租约共享，关闭一个
Thread 不撤销其他 Thread 的租约。

## 16.2 不透明载荷与通用上下文

载荷由格式标识、版本和原始 UTF-8 字符串组成。core 不要求 JSON、不解释字段、不格式化、
不改变数字、空白、换行或字符；摘要与容量按实际字节计算；未知格式和版本仍可存取。上层
需要 JSON 时在自己的 codec 边界解析。二进制通过有完整性保证的资源引用承载；普通资源
上下文只表达资源引用，实际嵌入媒体由 model 的无角色附件投影显式表达，避免完整日志被
自动展开。

工具结果分为完整业务载荷和当时实际交付给模型的上下文投影，两者共同提交；模型返回的
合法 function 参数也以原始字符串作为唯一载荷保存，不能在解析成功后丢弃空白、字段顺序或
数字原文——协议校验与展示解析是派生操作，历史请求编码复用保存的参数原文，执行关联摘要
使用实际传入 executor 的参数字节。工具不能指定 system 角色；框架根据调用身份构造工具
结果记录。工具名称或 MCP 前缀不能授予额外工作区访问权限；审批、结束 Turn、取消和状态
提交必须走可信控制接口，不能从载荷字段推断。core 的工具结果按事实提交顺序保存，model
对完整调用批次按原 assistant 调用顺序进行确定性协议投影：投影只重排同批次的结果，不更改
载荷、结果关联或已提交 effect；工具媒体同样按调用顺序排列，并放在完整结果批次之后；缺失和
重复结果明确拒绝。

通用上下文记录信封保存 assistant 发起的工具调用（稳定工具 ID、调用 ID、不透明参数），
不将调用藏入文本或业务载荷；后续模型请求仅凭冻结上下文即可重建调用与 ToolResult 关联，
上下文替换校验调用唯一性、结果归属及完整配对。一次 assistant 工具调用批次与对应结果之间
不插入新的上下文消息：通用上下文校验拒绝未完成批次被其他角色记录打断；Thread 的事实
/应用更新入口在存在待交付调用时拒绝插入上下文，宿主可在结果提交后重试。

历史使用 Studio 在 effect 提交时保存的投影，不调用当前工具、当前渲染器或当前配置重建旧正文；
载荷不可变，替换和删除保留历史版本。业务 decoder 不存在时仍可读取原始记录；无法解释继续执行必需的
状态时明确失败，不能替换为空值。私有上下文变更使用明确的设置/清空枚举表达，避免 JSON
null 往返混淆"未变化"和"清空"。

新建 Thread 的初始上下文由 Studio 显式提供，并在发布 owner 前提交，且需通过通用调用配对
校验；恢复 checkpoint 和非空初始上下文不能同时传入，防止使用当前工作区、Skill 或配置覆盖旧
内容。子 Thread 继承上下文时保留当前有效记录与已交付内容，只裁剪到完整工具调用批次边界；
不执行旧工具、不重渲染正文，也不继承可变模型会话；指令是否继承由宿主显式选择。

长期规则按内容版本冻结；动态上下文变化时追加完整快照，相同内容不重复追加；清空时追加
旧快照失效声明；压缩移除最新快照后重新补入当前值。Thread 接受上层提供的完整运行事实集，
按稳定 source ID 追加有变化的正文；省略已知 source 追加失效记录；所有记录保持 Runtime
来源，不提升为 system 指令。

## 16.3 模型调用契约

一次 prepared call 绑定同一模型实现、能力、工具声明及输入。通用 Thread owner 通过模型
会话的 prepare 冻结输入，准入后一次性发布请求与上下文；模型正文和下一份私有上下文在
同一快照提交。准备前/后取消不消费输入；准入后失败保留尝试事实；准入后取消仍保留模型
最后返回的完整候选输出或失败记录（包括已知用量），作为取消尝试的观察事实保存，不推进
当前正文、工具调用或私有 continuation——不能仅保留 usage 而丢弃已经收到的原始事实。
透明重试不再次扫描文件、刷新目录或追加输入。

prepared call 可携带模型实现给出的输入 token 估算，显式标注精确或近似；Thread 的容量政策
明确选择是否接受近似值及未知值，拒绝发生在输入准入和实际模型调用前，请求记录保留当次
实际使用的估算，不从字符数自行推算。prepared call 可携带 model 编码的工具投影材料：core
不解释其格式，随请求准入冻结并保存，原样传给该请求产生的工具调用；工具不能读取全局可变
模型目录来重新推测已受理请求的能力。prepared call 同时给出不透明请求元数据，记录实际
规范化声明、绑定与生成参数；即使调用失败也保留当时参数，不按当前配置重建。

显式重试使用新的 attempt ID 并记录 retry_of，复用失败尝试已准入的上下文和冻结工具租约，
不重复用户输入；仅当前上下文仍匹配且工具目录未撤销/改变声明时允许该重试，不匹配时要求
宿主准备新的执行请求。重试复用计划同时比较声明与类型化控制权限；executor 重连不改变
模型输入身份，但权限撤销使旧计划不可重试；retry_of 必须指向同一 Turn 已失败/取消的请求，
不允许通过修改引用伪造重试事实。传输内部透明重试由 model 保持单次 prepared input。

通用 ResourceReader 由宿主注入，模型请求捕获资源访问租约；读取结果按资源引用声明的字节
长度和 SHA-256 校验，缺失或被替换内容明确失败。core 不从路径或 URL 猜测资源，也不把
二进制强转字符串。资源服务绑定变更使旧 attempt 的显式重试租约失效，需新建请求；该执行
身份判断不加入模型 cache key。

模型会话的调用准入租约在所有克隆句柄间共享，一次只准入一个 invocation；关闭先封闭准入，
再等待在途 invocation 释放租约。模型 transport 的收包任务由会话显式关闭并等待退出，不能
仅依赖 Drop 后宣称 Thread 已关闭；会话关闭使用共享关闭 future，等待者被取消只放弃本次
等待，不丢弃连接或任务句柄。模型实现发生准备/执行 panic 后，动态会话入口标记不可再用；
Thread 保留失败与关闭重试能力，由宿主恢复时装入新模型会话。

摘要使用独立模型会话，默认复用当前绑定、已冻结工具声明和连续历史公共前缀，在尾部追加
摘要要求；不执行工具，不推进主会话 continuation；成功才提交替换，失败保留历史。文本
摘要请求设置 tool_choice 为 none 并移除 provider-hosted 工具；失败不静默删除历史或改参
重新调用，避免隐藏额外 attempt 和丢失用量。取消或超时后迟到的摘要不产生上下文替换；
压缩等待执行与私有会话关闭收束，再以失败事实返回已观察用量。原生压缩能力接收冻结的
模型请求，model 选择实际协议版本并验证唯一 checkpoint，连同实际 accounting 返回；core
不构造原生压缩模式参数，历史保留策略只组合已验证的替换材料。通用压缩配置仅表达
TextSummary 或 PreferNative，观测结果仅表达 Local 或 Native。文本 token 启发式由 model
提供并明确只属于近似估算；遇到媒体、加密 checkpoint 或无法确定 token 语义的原生材料时
返回未知，不回填零或压缩前估算。

真实模型的 Thread adapter 实现 core 模型端口；assistant 历史帧保存当时的 provider 调用
名称、原始参数和原生材料，后续工具结果根据旧帧配对，不用当前目录重写历史名称；非
assistant 来源不能提交 assistant 帧，未知帧版本阻止新调用但不修改已有历史。模型准备先
完成 native/custom 工具投影与能力校验，再冻结估算及执行请求；custom 工具的
function-fallback 包装属于模型协议，model 解包为原始文本交给工具，无法解包的模型输出
作为被拒绝的尝试保存，不路由到可执行工具。provider 私有历史是否可消费由 model 在实际
请求入口校验。托管工具由 model 工厂参数提供，准备时与本地声明合并并验证名称冲突，不
进入 core executor 注册表。模型失败可附带 producer 编码的不透明诊断事实，core 不解释
定价字段，随失败尝试保存并原样恢复，不伪造零费用；模型失败的显示保留失败类别与原始
原因，只报类别而丢弃原因的封装视为缺陷。

模型输出准入先校验请求身份、上下文 revision、工具目录和调用身份，再校验 Solo 批次；
整批准入成功前不执行任何工具。准入错误保留具体类型与拒绝的原始 attempt。只有 Solo
混批允许通用 Turn 循环追加框架纠正上下文后重新生成，每 Turn 最多两次，计入原有步骤
预算；其他一致性错误不自动恢复。纠正以新 attempt 关联被拒绝 attempt，从 canonical 已
提交历史准备，拒绝的 provider continuation 不成为已提交上下文；取消、关闭和持久化失败
不能被纠正覆盖。

## 16.4 扩展 CAS 与交互解析

通用 Thread 提供扩展批量 CAS：所有载荷保持不透明，更新分配新版本，删除保留墓碑和全局
版本水位；批次中任一冲突不写入部分状态。扩展状态不会自动进入模型上下文，也不能触发
审批或 Turn 控制，上层另行提交模型可见投影。应用更新（ApplicationUpdate）原子提交扩展
CAS 与上层提供的事实投影：先在候选状态验证两部分，任一失败都不发布；成功只产生一个
Thread effect，防止正文与业务状态处于不同版本；core 不尝试从 payload 重新计算投影。

工具可从只读扩展快照计算 CAS 变更，并随工具输出一起提交；注册显式授予扩展写入权限，
此类工具独占调用批次。core 原子应用扩展变更与工具结果；冲突保留完整 payload，标记失败
并附加框架拒绝说明，不部分更新业务状态。工具执行中取消后，完整返回值作为观察事实
保存，但不应用其扩展变更或 Turn 控制。Plan 与 workflow 的模型工具、CAS 参数、完成证据
校验和业务结果投影由 Studio 提供（见 [11](./11-thread-mode.md)、[13](./13-plan.md)）；
二者的 section ID 由 Studio 定义，core 统一校验当前请求中的 section ID 唯一性与原始正文
摘要，重复来源或摘要不符时拒绝冻结，不猜测哪个业务来源优先。

Thread 交互以不透明请求/回答载荷和显式 Pending/Resolved/Cancelled 状态保存；resolve
校验 revision，回答正文与状态在同一 commit 成立，并保持 Runtime 来源；payload 中的
approved 等业务字段不会被 core 解释。交互 resolve 可携带一条通用 continuation 输入：
core 在同一候选状态内校验响应、扩展 CAS、上下文投影和输入身份，再一次性提交；重复
提交只在响应和变更均相同时视为幂等，只返回相同回执，不重复入队。交互取消通过携带
预期版本的显式命令执行，Pending → Cancelled 与低权限的取消上下文在同一 commit 生效，
不构造空回答或业务扩展变更；过期命令和已经回答的交互拒绝取消。ask-user 工具返回
AwaitInteraction 和不透明问题载荷，core 分配与原调用绑定的交互 ID，并与工具结果一起
提交 Pending；该工具必须独占模型批次并具备注册授权，Turn 返回 WaitingInteraction，
回答通过显式 resolve 提交后才能继续模型步骤。存储压力不阻止已受理交互的事实收束，
续跑仍经过正常执行准入。

终态交互/权限事实的幂等回执与产生它的 effect 在同一 history 事务耐久化；一旦对应的 owner
effect window 批次被 durable 释放，重复 resolve 由 history 的持久回执回答或按冲突拒绝，
不回落到内存、不重放副作用（持久回执与可读条件见 [15](./15-session-storage.md) §15.3）。

## 16.5 能力归属与组合

配置值对象随解释它们的边界归属：指令配置归 Studio，Skill 扫描配置归 tool；Studio 持久化
并组合这些值，core 仅接收冻结后的上下文，不持有配置或目录发现政策。core 公共 API 不
镜像导出 provider 目录、凭据描述、hosted search 能力或 MCP 服务目录 DTO；Studio 配置
目录直接消费 model 构造的产品协议 DTO。模型配置解析（路由构造与 reasoning 参数解释）
集中在 model：装配入口接收已经构造的模型运行时及冻结调用参数，主循环与压缩共享同一份
已解释参数。

MCP 工具层只接收解析完毕的连接参数与凭据，不选择模型账号或内置服务；内置目录、启用
状态持久化及 provider 凭据选择由 Studio 组合。搜索的公共请求格式由独立上层协议承载：
独立搜索 HTTP 客户端与工具执行归 tool，Studio 根据模型能力选择并装配搜索后端；exclusive
搜索装配只包含选中的搜索能力，不先创建被隐藏的 workspace 工具。宿主原生工具的启用
条件由 Studio 按冻结模型绑定判断，作为同批工具目录变更发布；core 不按 provider
capability 选择工具。执行环境（本地/SSH、OS、shell dialect 与可执行路径）由 tool 探测，
Studio 随 Thread 资源绑定持有；每轮提示词从已装配资源读取环境事实。

LSP 服务只随 Studio 显式构造的 workspace 工具绑定，每轮模型引擎不取得语言服务实例，
文件工具在创建时捕获对应服务租约；LSP registry 接收宿主已经解析的工作区身份，登记一个
工作区不隐式淘汰其他工作区，关闭与回收由拥有租约的 Studio 生命周期明确驱动。工具工作
区组合对象（workspace 授权边界、LSP 通知和文件写入租约）归 tool；core 不返回该对象或
隐式读取进程 cwd 为其选择工作区，宿主按配置显式构造。物理路径校验、符号链接/reparse
point 检查、安全目录删除和工具路径策略归 tool 的 workspace 域；物理宿主指纹与工作区
组合绑定由 Studio 每 Thread 资源持有，每轮配置核对读取同一份冻结绑定，不重建工具实例。
标准文件工具通过冻结的文件后端执行，历史保存当时的完整结果及实际模型预览，恢复不
重新读取文件；命令执行的授权独立于文件访问授权，不能用 exec 的外部路径权限隐式放开
文件工具。

现役子代理工具的 schema、参数解析、历史分页和通知源属于 pl-tool，调用协调宿主提供的
端口；子代理查询、停止与关闭通过类型化宿主端口进入 Studio，caller 来自 core 分配的调用
身份，Studio 校验所属树和后代关系，拒绝跨树控制与自关闭。子代理创建通过 Studio 子
Thread 工厂解析 Profile、配额与资源绑定，工厂必须校验 caller 的创建权限；Studio 从同一
配置快照解析启用 Profile 与模型路由，旧产品入口与新工厂共用这一解析边界。Studio 在
子任务资源准备前预留身份和树内名额，准备中的任务同样受产品深度/数量限制；预留持有
独立取消令牌；现役默认策略保持仅 root 创建子任务、每树最多 16 个 Thread。子任务工厂
必须提供未发布资源的幂等回收端口：准备、装配或取消失败时先关闭已建立的 core Thread，
再回收未发布产品资源；回收失败保留 owner、父子关联及重试入口。物理 workspace 准备是
Studio 的产品资源职责；Git worktree 租约先记录准备事实，再执行创建及失败收束。Studio
新建 Thread 的种子明确区分模型上下文与不透明扩展记录：Profile 指令与选定工作区说明
进入上下文，创建 metadata 和完整工作区回执保存为扩展载荷。root 与 child 初始指令由
同一创建期捕获流程生成，复用已选中的远程文件服务和执行环境，保存配置/角色/项目文档
来源快照；动态 Skill 推荐不进入这份稳定前缀，root 冷恢复装入当前 checkpoint，不用当前
文档重写过去。

Studio 的标准工具装配使用 pl-tool 提供的稳定声明与工具构造器，显式接收同一配置快照中
的能力开关：关闭的能力不创建 executor、不获取 worker 资产，不能通过可选构造方法重新
启用；配置更新由宿主形成下一份目录后原子替换。Studio 的 helper 资产装配由产品资源模块
统一提供，本地命令后端持有可执行映像租约，嵌入式发布不依赖 PATH。产品附件宿主接口归
pl-tool，Studio 注入持久化与读取实现；准备媒体只在 model/Studio 适配边界传递。工具
媒体归档与 model 投影使用统一的工具层端口，MCP 与文件图片读取共享该端口。工具需要
对话背景时，读取产生本次调用的模型请求快照，而不是可变会话或尚未准入的消息；独立
搜索由 tool 筛选近期用户/助手文本，排除指令、运行时注入、工具结果和 provider 不透明
材料。provider 前缀缓存分组键不包含 temperature 或最大输出 token 等生成参数；模型、
账号/部署隔离、协议、指令、声明和会影响编码的选项继续参与分组。Trace 展示记录及
其产品事件格式属于 protocol 的 trace 交换域；trace 依赖 core，读取 Thread effect 与调用记录生成
诊断，观察过程不执行模型或工具。

## 16.6 工具执行与授权

通用 Thread 内核独占不透明工具注册表，模型步骤不从调用方直接接收另一份工具声明。每次
请求冻结声明及 executor，输出必须引用该计划中的工具且调用 ID 唯一；目录替换保留在途
executor 租约。工具输出的角色与调用关联由 owner 赋值。公开工具注册值不可克隆，装入
Thread 时转移实例所有权；仅 core 内部冻结执行租约可克隆；共享物理服务应由具体工具显式
捕获服务租约，不能借复制注册值在多个 Thread 间共享同一工具实例。不透明工具契约提供
显式 close：Thread 工具管理器保留已替换但仍归属该 Thread 的实例，关闭时逐一等待收束；
已成功关闭的实例不重复调用，失败实例及剩余实例保留用于重试。

结束 Turn 使用独立的类型化控制枚举；payload/context 中同名文本不触发控制。工具注册
显式授予结束权限，拥有该权限的调用必须独占模型工具批次；未授予权限却返回控制值时
记录工具失败，不结束 Turn。deferred 目录状态按稳定工具 ID 和原始声明保存，reveal 是
显式框架操作：发现工具通过工具输出的类型化 revealed_tools 请求揭示，注册必须显式授予
discovery 权限；core 先验证全部 ID，再与扩展 CAS、工具结果一起提交，取消或失败不改变
揭示状态，动态 payload 中同名字段不触发该操作。重连但声明不变保留揭示状态，删除或
改变声明清除旧状态；不根据 executor 代次重置可见前缀。

动态工具替换由同一 Thread owner 在长调用等待期间受理；已经冻结的请求和已经启动的
executor 租约不变，后续步骤使用替换后的目录；注册失败不改变当前目录，替换不关闭仍被
在途调用持有的资源。冻结 executor 不等于永久授权：准备结束准入前复核原工具计划的权限
仍有效，工具真正启动前再次检查；撤销或删除阻止尚未启动的副作用，已启动执行仍保存
事实；迟到结果不得应用已经撤销的框架控制权限；仅 executor 重连及新增其他工具不撤销
原调用。

工具授权身份与模型声明、executor 实例分离：宿主通过类型化注册接口提供不含凭据的策略
身份，权限策略变化时更换；core 只比较身份，不解析策略。更换身份阻止旧计划准入、旧
调用启动及旧任务取消权限继续使用，但不改变模型声明或缓存前缀。工具执行前可绑定宿主
执行策略（ExecutionPolicy）：core 通过类型化成功/失败决定是否调用 executor，不解析审批
JSON；等待结束后再次校验原 executor 的权限租约和任务存活状态。执行策略返回调用级
执行授予（ExecutionGrant），能力名由上层定义，core 不解释；工具仅消费可信调用上下文
中的授权能力，不读取模型参数中的授权标记；授权仅对当前调用有效，不进入模型声明、
不从冷历史恢复；物理 confinement 仍是工具后端不可被授权放宽的边界。文件后端按调用级
授权创建临时访问视图，保持原 workspace 根、写入范围与服务租约；仅本地 host-permitted
工作区可消费外部路径能力，受限 worktree、远程和容器默认不提供放宽视图。工具访问需求
由宿主装配的 assessor 从原始参数解释，core 只消费类型化访问需求并管理审批状态；未装配
assessor 时不给予额外访问能力。审批产品 DTO 直接投影 core 保存的许可请求、决定、时间
与原样响应载荷；UI 响应通过 Studio 解码后提交 revision 校验的类型化命令，未知审批载荷
格式投影为原始记录，不能呈现为可执行的审批控件。

自动审查模型是 Studio 装配的辅助调用，使用冻结模型绑定和独立模型会话；core 仅提交
类型化审查请求、传播取消并等待审批结果；未配置 reviewer 时拒绝需要审查的调用，不回退
为自动批准。可展开 panic 的模型/工具实现边界将 panic 转成类型化失败并保留诊断，防止
owner 在记录终态前消失；无法得到 provider 已知用量时保持未知；该机制不宣称恢复外部
副作用。工具失败允许同时返回已经观察到的完整 payload/context：core 保存实际结果及
失败事实，但不应用失败结果中的状态更新、交互或 Turn 控制；错误源链作为诊断文本保存，
检测重复源并限制异常链深度，明确标记截断。

内置的 todo、session note 工具从 Thread 扩展快照读取原始状态：todo 工具自身校验
checklist 并生成载荷/上下文/CAS 变更，相同内容不写新扩展版本；note 工具正文保留原始
换行和 Unicode，不自动进入上下文，写入回执使用 Thread 扩展水位给出实际候选版本。
finish_turn 工具提交完整非空 message，不设应用层长度上限，Turn 结束使用注册授权的类型化控制。

## 16.7 计量与回执

model 保存完整的归一化响应，而非仅保留正文与调用列表：响应 ID、返回的模型标识、
用量、定价、编排指标及时间信息同属不可变回执；回执同时记录请求模型、provider 实例、
协议及脱敏隔离身份，产品层通过 model 的解码接口读取，core 不理解这些字段；用途只是
诊断分类，不改变工具权限或调度。Studio 的计费记录装配只接收已保存的 context_window
和实际 accounting，不读取当前模型目录或价格目录；未知容量保持未知。

计费记录以独立 purpose 字符串描述调用用途，主循环、摘要、审查和标题在各自调用点显式
赋值；未知历史用途保持缺省，不从 inference ID、工具名或模型名猜测，也不参与执行控制。
Studio 在保留会话总费用的同时按 purpose 汇总费用与未定价标记，并通过 typed DTO 暴露；
缺少用途的历史费用归入未知用途，不能移入主循环；重复 inference 不重复计入任何分组。
辅助审查无论批准、拒绝还是模型失败，均记录已收到的 provider accounting；取消后的
reviewer 完成自身请求收束与 accounting 受理，再返回框架拒绝结果。

trace 汇总已验证日志中的真实模型用量：取消/失败/拒绝响应发生的消耗也计入，Running
不重复计费；缓存读写独立汇总但不再加到输入总量；缺失或计数溢出保持未知，输入估算
不参与真实 usage 汇总。

## 16.8 资源与物理服务

Studio 的文件资源库按完整字节摘要寻址：写入先复制到同目录临时文件并同步，再以不
覆盖已有对象的方式发布；相同内容复用已有对象，冲突对象必须校验而不能静默覆盖。资源
引用自身携带长度、摘要和媒体类型，读取可据此恢复，不建立具体工具结果表。本地命令
归档只读取已排空的本地 capture；远程 capture 必须由对应远程读取适配器处理。远程
helper 协议提供有界文件范围读取与显式文件写入模式：归档客户端逐段核对偏移、总长度及
实际返回字节数，拒绝截断或长度变化，逐段写入本地暂存文件后再发布资源；单帧上限不能
变成完整输出的截断上限；失败保留远程源 capture，重试只读取输出、不重新执行命令。

文件写入模式贯穿工具参数、工作区后端与 helper 协议：create 使用排他创建，append 使用
追加文件句柄，overwrite 使用原子替换；远端不以读取旧内容后覆盖的方式模拟追加。工作区
文件原子覆盖保留已有目标的文件权限，新文件采用普通文件创建权限并遵守 umask。附件
writer 的唯一契约是有序原子批量写入，单图写入也经过同一接口，不提供逐图循环冒充批次
提交的兼容构造。

MCP 动态工具绑定固定服务租约与声明，执行器解析自身参数后调用同一租约；结果中的图片、
音频和嵌入 blob 按精确字节归档为稳定资源引用，业务结果保留其余结构与元数据。归档
失败使用显式的 mcp-unarchived 结果格式保留收到的完整协议材料，不伪造资源引用，也不
声称已具备正常媒体投影；模型仅收到失败说明，历史仍可查看原始材料。MCP 资源目录、
模板和读取 façade 与服务工具使用同一冻结租约：资源查询只路由到该租约声明支持
resources 的服务，未指定服务时按稳定服务顺序聚合；读取结果保留完整返回信封和元数据，
嵌入二进制转换为持久资源引用，读取或归档失败不产生默认空结果。

宿主辅助命令的超时也必须经过物理收束：本地使用统一进程组/Job Object 包装，同时等待
退出与两路输出；远程保留原退出接收器和输出读取任务，发送终止后继续等待。终止请求
失败不能伪装成执行已结束，退出或排空失败保留明确诊断。

定向 interrupt 与新输入打断保存 `TurnState::Interrupted`；关闭或取消令牌保存 `Cancelled`。
内部取消错误仍用于收束在途执行，不能据此丢失历史库中的实际停止原因。

Studio 将 Interrupted 映射为取消展示的强类型原因 interrupted；没有结束耗时的恢复中断
投影为 recovery，避免把运行中的定向打断误标为恢复。FRB 与 Dart 保留该原因。
