# 27 - 极简核心、动态载荷与上下文重放

本章定义职责边界与执行契约。实现是否满足合同以实际依赖、公共签名、生产调用路径和验证记录为准。

## 所有权与依赖

`pl-core` 拥有 Thread、Turn、模型和工具调用契约、通用上下文、交互、任务、消息及冷存储。
`pl-model` 和 `pl-tool` 实现核心接口，依赖 core，二者不相互依赖。`pl-trace` 消费核心观察接口。
core 不依赖 model、tool、Studio、trace 或 protocol，包括测试依赖。

`pl-studio-runtime` 拥有配置持久化、项目、Profile、Mode/workflow/plan、子代理协调和唯一装配入口。
root、child 和冷恢复使用同一装配路径。TurnEngine 不提供默认工具、Git、Skill 或 profile 自动安装入口；
pl-tool 的 WorkspaceTools 只构造工具组，Studio 显式注册并单独加入业务 plan/workflow 工具。
文件、容器、Skill 工具、exec、命令任务管理与 SSH 客户端归 pl-tool；宿主进程创建 flags 的唯一实现归
pl-remote-helper::process。Bridge 经 Studio 的 SSH 接口类型映射，不直接组合工具运行时。
每个 Thread 独占工具管理器、工具实例及模型会话；物理
服务按身份与隔离边界通过租约共享。关闭一个 Thread 不撤销其他 Thread 的租约。

## 不透明载荷与上下文

载荷由格式标识、版本和原始 UTF-8 字符串组成。core 不要求 JSON、不解释字段、不格式化、不
改变数字、空白、换行或字符；摘要与容量按实际字节计算。未知格式和版本仍可存取。上层需要
JSON 时在自己的 codec 边界解析。二进制通过有完整性保证的资源引用承载。

工具结果分为完整业务载荷和当时实际交付给模型的上下文投影，两者共同提交。上下文只定义角色、
来源、调用关联、文本、资源引用和不透明内容。工具不能指定 system 角色；框架根据调用身份构造
工具结果记录。用户交互由 core 返回 Resolved/Pending，取消明确报错而不合成空回答；
工具层负责 schema 和回答正文编码。工具名称或 MCP 前缀不能授予额外工作区访问权限。审批、结束 Turn、取消和状态提交必须走可信控制接口，不能从载荷字段推断。

历史使用已保存的投影，不调用当前工具、当前渲染器或当前配置重建旧正文。载荷不可变，替换和
删除保留历史版本。业务 decoder 不存在时仍可读取原始记录；无法解释继续执行必需的状态时明确
失败，不能替换为空值。

## 模型输入与缓存

长期规则按内容版本冻结；动态上下文变化时追加完整快照，相同内容不重复追加。清空时追加旧快照
失效声明；压缩移除最新快照后重新补入当前值。Skill 推荐、时间和业务运行状态不进入动态重建的
历史前缀。普通执行只追加模型可见记录，压缩、回退和重建使用显式替换。

一次 prepared call 绑定同一模型实现、能力、工具声明及输入。准入前取消不消费输入；准入后失败
保留尝试事实。模型输出与私有恢复材料在同一 Thread commit 成立；物理连接的推测状态不能绕过
该提交。透明重试不再次扫描文件、刷新目录或追加输入。

执行器代次与模型可见声明的内容身份分离；deferred 目录只因名称、schema、组或说明变化而失效，
重连且声明不变时保留揭示状态。图片工具只接收宿主解析后的数量、大小和格式限制，
Studio 根据实际模型的输入源与重放能力决定是否注册；pl-tool 不导入模型类型。provider 的编码、cache key、媒体处理和 usage 归 model；
core 不通过递增 Thread revision 判断服务端缓存。缓存读写仍占上下文容量，未知 usage 保留未知。
结构稳定性和真实 provider 命中分开验证。

摘要使用独立模型会话，默认复用当前绑定、已冻结工具声明和连续历史公共前缀，在尾部追加摘要
要求；不执行工具，不推进主会话 continuation。成功才提交替换，失败保留历史。

## 冷存储与重放

SQLite 是 core 的可选后端，默认纯内存。存储通用 Thread commit、不可变记录、载荷、派生索引与
checkpoint，不按工具或业务类型建表，不执行业务 reducer。完整载荷、模型投影、关联、水位、
任务终态和模型材料在同一提交中保存。索引和 checkpoint 可重建，不形成第二套事实源。

热状态先提交，writer 异步追写；默认最多五秒或 64 条触发，flush 固定调用时水位。默认每 Thread
64 MiB、每 store 256 MiB 待保存量暂停新的执行受理，低于一半后恢复；取消、查询、交互收束和保存
重试仍可用。已受理任务保留真实结果，因此受理阈值不是进程内存硬上限。

历史重放只应用已保存事实，不调用模型或工具。冷恢复后继续由 Studio 使用当前配置重新装配，
遗留执行收束为 interrupted，不重放副作用或继承旧 executor 审批。物理资源引用必须具备可验证的
内容保存责任，仅保存路径不能保证重放。

旧格式可以明确重置：Studio 独占锁定、收束连接、处理 WAL/SHM、备份并协调产品关联重建后才发布。
不删除配置、凭据、SSH 密钥、工作区或无法确认所有权的资源。core 不自动破坏性重建数据库。

## 验收

以未知格式、非 JSON 文本、空白、大数字、Unicode 与内嵌 NUL 验证字符串无损；验证历史替换与删除、
原子提交、损坏检测、无副作用重放和模型投影不被新版渲染器改写。验证 Thread 资源隔离、取消及
迟到结果、动态注册代次、保存压力和关闭重试。真实缓存命中只能由 provider usage 证明。

配置值对象随解释它们的边界归属：指令配置归 Studio；Skill 扫描配置归 tool。Studio 持久化并组合这些值，core 仅接收冻结后的上下文，不持有配置或目录发现政策。

MCP 工具层只接收解析完毕的连接参数与凭据，不选择模型账号或内置服务。内置目录、启用状态持久化及 provider 凭据选择由 Studio 组合；运行时能力开关同样由 Studio 传给工具目录。

搜索的公共请求格式由独立上层协议承载。独立搜索 HTTP 客户端与工具执行归 tool；Studio 根据模型能力选择并装配搜索后端。core 不选择搜索服务或持有搜索工具实现。

宿主原生工具的启用条件由 Studio 按冻结模型绑定判断，作为同批工具目录变更发布；core 不按 provider capability 选择工具。工具目录仅接受通用显隐决策，不反向引用 Studio 搜索策略。

工具调度策略中的扩展字符串不触发 core 行为。Studio 解释 tool 声明的模型调用扩展并校验副作用权限；model 生成 provider caller/output schema。冻结 ToolPlan 只保存已交付声明，不重新生成这些字段。

工具交付的模型投影在 core 调度、缓存命中和批量提交时保持原样；不得再次解析 JSON、截断或替换为缓存回执。缓存命中作为单独框架事实记录，资源引用随内容保留。容量不足由上下文准入/压缩策略处理；provider 原生工具要求的外层编码由 model 完成。

产品显示投影与完整 payload、模型 context 分离。涉及秘密答案等业务脱敏时，由内容所有者产生显示投影；core 不按工具名或业务字段判断脱敏，不覆盖完整载荷与实际模型上下文。

失败缓存由工具显式提供失败投影和可复用判定；未提供判定时失败不缓存。core 不按工具名或业务错误类型猜测稳定性，缓存保留工具给出的失败正文，复用来源单独用于诊断。

缓存身份不从参数中的路径推断项目视图。任意参数字符串都只是缓存输入，不能绕过失效代次。参数摘要在进入缓存锁前计算；失效后新的受理使用新代次，不等待旧代次的相同键执行。

Plan 工具不维护独立状态内核，读取 Thread 当前扩展状态并计算候选变更。提交和交互失败回退均比较预期版本；状态已变化时拒绝覆盖，不能用工具私有快照回滚其他已提交事实。

Plan 的模型工具声明、参数校验、确认问题与结果渲染归 Studio。工具组在 Thread 装配时创建，后续直接读取 Thread 当前状态，不为每个 Turn 再复制 Plan 内核。

Workflow 的模型工具、CAS 参数、完成证据校验和业务结果投影由 Studio 提供。执行器引用 Thread working set；提交时比较读取的完整状态，拒绝覆盖并发更新。

每个步骤先刷新工具和宿主上下文投影，再冻结实际模型请求。core 保存投影 section，不持有 Mode 注册对象；上层渲染当前事实，历史仍使用已提交正文，不能反向调用当前渲染器重建。

Mode 注册来源、不可变目录、状态图编译与模型上下文渲染由 Studio 独占；core 不接受或返回 RegisteredThreadMode、ThreadModeManager 或编译后的产品状态图。

Plan 与 workflow 的 section ID 由 Studio 定义。core 不保留这些业务命名空间；它统一校验当前请求中的 section ID 唯一性与原始正文摘要，重复来源或摘要不符时拒绝冻结，而不是猜测哪个业务来源优先。

任务完整结果在内存提交时冻结编码与内容身份；异步 writer 复用相同字符串，只校验引用归属、长度和摘要，不调用结果编码器。恢复任务目录只验证已保存载荷，结果解码延迟到需要消费该格式时。

工具完整结果统一保存为 OpaquePayload，删除 Text/JSON 内容分支。任务结果 wire 保留 format/version/content 字符串信封；默认模型任务视图只交付已准备的模型正文，不自动暴露完整业务载荷。

每次工具交付使用通用不可变记录保存调用身份、完整 OpaquePayload 和已提供的 ContextContent。直接工具、框架结果及任务受理回执均随对应模型历史在同一 checkpoint 提交；媒体记录通过相同调用身份关联，不借显示正文替代完整载荷。

模型返回的合法 function 参数也以原始字符串作为唯一载荷保存，不能在解析成功后丢弃空白、字段顺序或数字原文。协议校验与展示解析是派生操作；历史请求编码复用保存的参数原文。

ToolInput 的执行载荷是原始字符串。动态 executor 自行解码；typed-tool adapter 显式选择 JSON 解码。缓存判定接收同一原文，core 缓存身份不格式化参数。

执行关联摘要使用实际传入 executor 的参数字节；诊断和交付记录也保留模型返回的参数原文。解析后的显示值不能成为另一份调用身份或历史参数来源。core 的工具进度只描述通用执行状态，不按业务工具名推断工作流或协作语义。

工具访问需求由宿主装配的 assessor 从原始参数解释；core 只消费类型化访问需求并管理审批状态。未装配 assessor 时不给予额外访问能力；路径字段、patch 语法和工具名称属于 tool。

自动审查模型是 Studio 装配的辅助调用，使用冻结模型绑定和独立模型会话。core 仅提交类型化审查请求、传播取消并等待审批结果；未配置 reviewer 时拒绝需要审查的调用，不回退为自动批准。

辅助审查无论批准、拒绝还是模型失败，均记录已收到的 provider accounting；使用冻结绑定及实际返回模型，未知 timing 不补零。取消后的 reviewer 完成自身请求收束与 accounting 受理，再返回框架拒绝结果。

计费记录以独立 purpose 字符串描述调用用途，主循环、摘要、审查和标题在各自调用点显式赋值。未知历史用途保持缺省，不从 inference ID、工具名或模型名猜测，也不参与执行控制。

Studio 在保留会话总费用的同时按 purpose 汇总费用与未定价标记，并通过 typed DTO 暴露。缺少用途的历史费用归入未知用途，不能移入主循环；重复 inference 不重复计入任何分组。

执行环境（本地/SSH、OS、shell dialect 与可执行路径）由 tool 探测，Studio 随 Thread 资源绑定持有。core 不探测 shell，也不通过 remote helper 启动环境探测进程；每轮提示词从已装配资源读取环境事实。

core 的 SQLite 后端通过显式 `sqlite` feature 编译；默认运行不依赖 ORM 或数据库文件锁。Studio 作为持久化宿主显式启用该 feature，数据库集成测试也必须显式选择同一 feature。最终验收分别检查 core 无默认 feature 和 SQLite 组合。

workspace 的 feature 合并不能证明 core 默认构建独立：CI 和最终本地门禁在 workspace 检查之外，分别执行 `cargo check -p pl-core --no-default-features --all-targets` 与 `cargo check -p pl-core --no-default-features --features sqlite --all-targets`。这两个命令仅验证 feature 组合，依赖倒置仍须单独核对 manifest。

LSP 服务只随 Studio 显式构造的 workspace 工具绑定，不再经 TurnEngine 或其 builder 转发。每轮模型引擎不取得语言服务实例；文件工具在创建时捕获对应服务租约。

ToolWorkspace 是 tool 的资源组合对象，持有 workspace 授权边界、LSP 通知和文件写入租约。core 不返回该对象或隐式读取进程 cwd 为其选择工作区；宿主按配置显式构造。

provider cache key 由 model 根据显式隔离范围与已冻结的 provider/model/指令/声明身份生成；上下文追加、诊断 generation、时间和 Thread ID 不参与 key。Studio 默认使用 provider 配置身份作为隔离范围，不使用会话 ID。缓存是否实际命中仍以 provider usage 为准。

model 复用 workspace 已有 SHA-256 依赖计算缓存提示摘要，不增加新的第三方库；公开 API 不暴露该依赖类型。诊断 scope 标签不写入实际前缀或请求属性摘要，避免产品角色标签导致无内容变化的 key 轮换。

工具声明的 JSON 键规范化和 provider 工具排序由 model 的单一编码入口负责，正常请求与摘要调用都经过该入口。数组保持原有顺序；core 不自行遍历或改写 schema。

记录来源由 core 分配的保留 ID 区分，不能从载荷 format 推断框架类型。上层格式可以使用任意非空命名空间（包括 pl 前缀）；只有保留 ID 上的框架记录会进入框架解码器。未知载荷的保存、删除和恢复不按 format 前缀过滤。

通用历史提交类型和纯重放位于始终可用的 core storage 模块，独立于 SQLite feature。重放校验 Thread 归属、连续提交序号和记录信封，应用追加/替换/删除，不运行模型、工具或上层解码器。

增量重放状态只在整个 commit 验证和应用成功后推进水位。无效删除、归属错误或缺失提交不能留下部分更新；调用方可以保留有效水位继续诊断或重新读取，不执行任何模型或工具副作用。

模型 transport 的收包任务由会话显式关闭并等待退出，不能仅依赖 Drop 后宣称 Thread 已关闭。关闭先封闭调用、等待执行收束，再关闭模型会话；关闭错误保留 Thread owner 和重试入口。

模型会话的调用准入租约在所有克隆句柄间共享，一次只准入一个 invocation。关闭先封闭准入，再等待在途 invocation 释放租约；已排队调用在取得租约后重新检查关闭状态。租约是资源生命周期控制，不是持有数据锁调用 provider。

会话关闭使用由会话持有的共享关闭 future。等待者被取消只放弃本次等待，不丢弃连接或 JoinHandle；后续关闭继续等待相同任务，不重复创建收束任务或依赖不可确认的 Drop。

Provider 配置、连接模式、能力与协议类型只从 pl-model::provider 导入，core 根模块不提供镜像门面；产品消费者与现役 provider 实现同步使用定义方路径。

模型元数据、输入能力、参数与价格目录从 pl-model::model 导入；core 不再通配镜像这些类型。工具层通过宿主转换得到所需通用限制，不反向依赖模型目录。

文本摘要请求保留已冻结历史正文和本地工具声明，只在尾部追加摘要要求；设置 tool_choice=none 并移除 provider-hosted 工具。失败不静默删除历史或改参重新调用，避免隐藏额外 attempt 和丢失用量；由上层明确选择新的恢复尝试。

原生压缩请求同样保留已冻结的工具正文与调用关联，不在 core 按近似字符数替换为截断消息。provider 拒绝容量时保留失败 accounting 和原历史，由宿主另行决定恢复动作。

通用 Thread owner 通过 ModelSession.prepare 冻结输入，准入后一次性发布请求与上下文；模型正文和下一份私有上下文在同一快照提交。准备前/后取消不消费输入，准入后失败保留尝试事实，迟到输出不能推进私有上下文。Studio 通过同一 Thread 装配入口连接模型、工具与冷存储。

通用 Thread 内核独占不透明工具注册表，Step 不从调用方直接接收另一份工具声明。每次请求冻结声明及 executor，输出必须引用该计划中的工具且调用 ID 唯一；目录替换保留在途 executor 租约。工具输出的角色与调用关联由 owner 赋值。

新 Thread 的关闭命令封闭后续执行受理；失败保持 Closing 快照与模型 owner，允许重复关闭。工具交付保留 Success/Failed 类型化终态，失败正文是本次真实交付内容而不是业务载荷中的调度字段。

准入后取消仍保留模型最后返回的完整候选输出或失败记录，包括已知用量；这些材料作为取消尝试的观察事实保存，不推进当前正文、工具调用或私有 continuation。不能仅保留 usage 而丢弃已经收到的原始事实。

通用 Thread 的上下文替换采用预期 revision 检查，记录替换原因及前后快照。替换拒绝重复记录 ID 和未交付工具调用，成功后清空 canonical 私有材料，下一次准备必须依据新上下文重新对齐。旧快照保持可查看，失败不修改当前上下文。

通用 Thread 接受上层提供的完整运行事实集，按稳定 source ID 追加有变化的正文；省略已知 source 追加失效记录。重建/压缩后，当前事实或失效声明缺失时重新追加；所有记录保持 Runtime 来源，不提升为 system 指令。

不透明工具契约提供显式 close。Thread 工具管理器保留已替换但仍归属该 Thread 的实例，关闭时逐一等待收束；已成功关闭的实例不重复调用，失败实例及剩余实例保留用于重试。冻结计划只延长执行器租约，不转移关闭所有权。

公开工具注册值不可克隆，装入 Thread 时转移实例所有权；仅 core 内部冻结执行租约可克隆。共享物理服务应由具体工具显式捕获服务租约，不能借复制 Registration 在多个 Thread 间共享同一工具实例。

通用上下文记录信封保存 assistant 发起的工具调用（稳定工具 ID、调用 ID、不透明参数），不将调用藏入文本或业务载荷。后续模型请求仅凭冻结上下文即可重建调用与 ToolResult 关联。上下文替换校验调用唯一性、结果归属及完整配对。

PreparedModelCall 可携带模型实现给出的输入 token 估算，显式标注 Exact 或 Approximate。Thread 的容量政策明确选择是否接受近似值及未知值；拒绝发生在输入准入和实际模型调用前，请求记录保留当次实际使用的估算，不从字符数自行推算。

通用 Thread 的 bounded Turn 循环由同一个 owner 完成模型准入、工具执行、结果提交和下一步骤。用户输入只在第一步追加；达到模型步骤限制前收束该步已经返回的工具调用，保留完整配对历史，下一次调用不重复追加原输入。

结束 Turn 使用独立 ToolControl 枚举；payload/context 中同名文本不触发控制。工具注册显式授予结束权限，拥有该权限的调用必须独占模型工具批次。未授予权限却返回控制值时记录工具失败，不结束 Turn。

新 Thread 发布快照时形成同序号的不可变 commit delta。正常上下文只保存追加记录，attempt 引用已提交的 input revision，模型输出与私有材料在同一 delta；重放不创建模型或工具实例。该日志是异步冷后端的唯一受理材料。

Thread 日志重放验证请求从 Running 单向转为终态，原 turn/attempt/input revision/冻结工具声明不能被终态记录改写。模型已提交输出必须匹配请求身份；Context 的调用信封可暂时存在待交付调用，但不能存在孤立或重复结果。

新 Thread commit 的冷编码是版本化不透明信封；嵌套模型/工具 payload 保留各自 format/version/content。错误源编码为可查看的错误链，恢复诊断不实例化 provider 或插件异常类型；缺少工具业务解码器不影响提交记录加载。

新 Thread 可显式挂接 ColdStore；内存提交先成立，随后非阻塞受理其编码。未受理日志始终由 Thread 保留，flush 重试并更新独立 durability 水位。SQLite 适配器保存通用不可变提交载荷，不运行上层解码器；存储错误暂停新的模型步骤，既有结果仍可提交。

挂接冷存储的 Thread 关闭先提交资源终态，再 flush 该终态。对外只有 durable 水位覆盖关闭 commit 才显示 Closed；等待保存或保存失败时仍显示 Closing，并保留 owner、日志和重试入口。重复关闭不重新释放已确认关闭的模型或工具。

Thread commit 在首次发布时冻结一次冷编码，后续保存受理重试只复用相同编码。错误 source 的 Display 实现或外部对象变化不能改变已提交字节、长度和摘要；编码失败与日志一起保留，不改写为默认对象。

新 Thread 在模型步骤准入前检查 writer 报告的 pending bytes，加上自身尚未受理的冻结编码。64 MiB/Thread、256 MiB/store 暂停新步骤；32 MiB/128 MiB 提示压力并作为恢复水位。该阈值不拒绝既有工具真实结果和关闭保存。

已提交的 Thread 冷记录不套用普通资源元数据的单条 1 MiB 限制。无论结果大小，已成立的事实必须进入 writer；新的执行受理由待保存字节阈值暂停，不能丢弃当前提交来满足阈值。

Thread::restore 先纯重放已保存 commit，再产生恢复收束提交：遗留 Running 尝试标记 Interrupted，未配对工具调用写入明确的中断结果，不执行工具或模型。恢复接收新模型实例、清空旧私有接续和工具注册；历史载荷及旧终态保留，新执行须由宿主重新装配。

Thread commit 保存明确的 thread_id，恢复入口同时验证外层存储归属、序号键和提交归属。私有上下文变更用 Set/Clear 枚举，避免 Option<Option<Payload>> 在 JSON null 往返时混淆“未变化”和“清空”。

显式重试使用新的 attempt ID 并记录 retry_of，复用失败尝试已准入的上下文和冻结工具租约，不重复用户输入。仅当前上下文仍匹配且工具目录未撤销/改变声明时允许该重试；不匹配时要求宿主准备新的执行请求。传输内部透明重试仍由 model 保持单次 prepared input。

重试复用计划同时比较声明与类型化控制权限；executor 重连不改变模型输入身份，但权限撤销使旧计划不可重试。日志中的 retry_of 必须指向同一 Turn 已失败/取消的请求，输入版本和冻结声明必须一致，不允许通过修改引用伪造重试事实。

通用 ResourceReader 由宿主注入，ModelRequest 捕获 ResourceAccess 租约；读取结果按 ResourceReference 声明的字节长度和 SHA-256 校验，缺失或被替换内容明确失败。core 不从路径或 URL 猜测资源，也不把二进制强转字符串。

资源服务绑定变更使旧 attempt 的显式重试租约失效，需新建请求；同一 ResourceAccess 的克隆不构成绑定变化。这个执行身份判断不加入模型 cache key，资源实际内容身份仍由稳定引用摘要决定。

新 Thread 提供通用 extension 批量 CAS，所有载荷保持 OpaquePayload；更新分配新版本，删除保留 tombstone 和全局版本水位。批次中任一冲突不写入部分状态。扩展状态不会自动进入模型上下文，也不能触发审批或 Turn 控制，上层另行提交模型可见投影。

ApplicationUpdate 原子提交扩展 CAS 与上层提供的事实投影。先在候选状态验证两部分，任一失败都不发布；成功只产生一个 Thread commit，防止正文与业务状态处于不同版本。core 不尝试从 payload 重新计算 projection。

工具可从只读扩展快照计算 CAS 变更，并随 ToolOutput 一起提交。注册显式授予扩展写入权限，此类工具独占调用批次。core 原子应用扩展变更与工具结果；冲突保留完整 payload，标记失败并附加框架拒绝说明，不部分更新业务状态。

工具执行中取消后，完整返回值作为观察事实保存，但不应用其扩展变更或 Turn 控制。ToolDelivery 分别保存 observed output 与实际 delivered_context；模型只收到框架中断结果以维持调用配对，不接收迟到业务正文。历史重放使用 delivered_context，不能重新投影 observed payload。

一次 assistant 工具调用批次与对应结果之间不插入新的上下文消息。通用上下文校验拒绝未完成批次被其他角色记录打断；Thread 的事实/ApplicationUpdate 入口在存在待交付调用时拒绝插入上下文，宿主可在结果提交后重试。

通用 Thread 消息按稳定 message ID 幂等受理，保留完整载荷和上层提供的 context。消费水位仅与模型请求准入同 commit 推进；准备失败或准入前取消不消费。显式重试只复用旧冻结输入，不把后来抵达的消息塞入该重试请求。

通用 bounded Turn 的 Running 和终态作为独立 Thread 日志事实保存，不能只依赖调用方返回值。恢复将遗留 Running Turn 收束为 Interrupted；Turn 与模型 attempt 分别记录，步骤限制和工具完成有不同终止原因。

Turn 取消时，已准入但尚未启动的工具调用以取消结果收束，不执行副作用；这些结果与 Turn 取消终态同 commit 发布。Thread 关闭也先收束未启动调用，再关闭工具实例，避免留下无法配对的结束历史。

Thread 中断句柄只持有当前命令的子 CancellationToken，不共享可变 transcript 或任务状态。中断在命令队列之外生效，不取消调用方复用的父 token，也不会影响下一执行代次；模型/工具结果仍由 owner 收束并提交。关闭会先请求中断，再等待有序关闭命令。

关闭发起时同步封闭活跃命令门禁并取消当前代次；即使 Close 尚在队列中，owner 也拒绝尚未开始的执行和变更命令。Journal、flush 和关闭重试仍可处理，关闭等待被取消不会重新开放受理。

可展开 panic 的模型/工具实现边界将 panic 转成类型化失败并保留诊断，防止 owner 在记录终态前消失。无法得到 provider 已知用量时保持未知；该机制不宣称恢复外部副作用或支持 panic=abort 进程内恢复。关闭 panic 保留关闭进度供重试。

新框架的独立调用示例位于 `code/pl-core/examples/minimal_thread.rs`：实现 ModelSession 和 Tool，Thread 独占注册实例，以非 JSON 字符串完成模型—工具循环，再编码并纯重放日志。示例默认内存运行，SQLite 通过 ColdStoreHandle 显式挂接。示例只展示独立用法；全量验收仍以各层实际检查记录为准。

Trace 展示记录及其产品事件格式属于 protocol 的 trace 交换域；pl-trace 不再作为 core/model 的类型门面。pl-trace 依赖 core，读取 Thread commit 生成诊断，观察过程不执行模型或工具。旧产品格式迁移仅保留 wire 投影，新的核心日志不依赖该格式。

删除无消费者的旧 output_format 捕获/生命周期投影/脱敏门面，不为不存在的调用方保留兼容实现。现役工具通过 pl-output 和各自 adapter 处理输出；core 的通用 ToolOutput 只保存载荷、实际 context 与可信控制。

新 Thread 的交互以不透明请求/回答载荷和显式 Pending/Resolved/Cancelled 状态保存。resolve 校验 revision，回答正文与状态在同一 commit 成立，并保持 Runtime 来源；payload 的 approved 等字段不会被 core 解释。Plan reducer 由 Studio 在该边界解释业务。

交互 resolve 接收宿主计算的 ExtensionMutation，回答状态、实际上下文和扩展变更一起 CAS 提交。冲突时仍保持 Pending，重复回答只有在响应和变更均相同才视为幂等。core 不从回答载荷中的业务字段推导状态机命令。

model 的缓存隔离摘要覆盖 provider 配置身份、部署地址、凭据及配置请求头，输出不含明文凭据；请求头按规范化名字稳定排序。切换账号/项目/部署会改变隔离，执行 ID、Thread ID、诊断时间与自动生成的传输头不参与该摘要。

Thread 实现按职责拆为公开状态契约、句柄、owner 生命周期、模型步骤、工具执行、上下文替换和通用状态模块；只有 owner 发布 canonical commit，各模块不建立第二份可变执行状态。

新 ToolManager 的 deferred 状态按稳定工具 ID 和原始声明保存，reveal 是显式框架操作。重连但声明不变保留揭示状态，删除或改变声明清除旧状态。冷恢复保存声明身份，重新注册时再与当前定义核对；不根据 executor 代次重置可见前缀。

发现工具通过 ToolOutput 的类型化 revealed_tools 请求揭示，注册必须显式授予 discovery 权限。core 先验证全部 ID，再与扩展 CAS、工具结果一起提交，取消或失败不改变揭示状态；动态 payload 中同名字段不触发该操作。

模型实现发生准备/执行 panic 后，动态会话入口标记不可再用，旧 prepared call 也不能继续发起调用；Thread 保留失败与关闭重试能力，由宿主恢复时装入新模型会话。关闭开始即封闭该动态会话的准备/执行入口。

Studio 的计费记录装配只接收已保存的 context_window 和实际 accounting，不读取当前 ModelInfo 或价格目录。模型配置解析仍由模型绑定层完成，未知容量保持 None。

Studio 持有默认摘要提示词、用户摘要要求和摘要展示前缀，并显式装配压缩策略。未配置策略时不自动压缩，手动压缩返回明确配置错误；core 的通用配置默认值不包含 Studio 产品文案。

ColdStore 压力快照同时报告后台 writer 错误，Thread 在模型准入前检查并保留类型化 source；公开持久化快照中的字符串仅用于展示，不能作为唯一错误状态或靠解析文本决定恢复。flush 重试成功才解除失败状态。

模型步骤在准备开始和请求实际准入前分别检查共享冷存储压力/错误与关闭门禁。准备期间其他 Thread 推高 writer 压力时，不启动该 prepared call，也不消费本轮输入和消息；已准备资源随调用句柄释放。

现役 complete 工具已提供新不透明 Tool 注册入口：业务校验仍由 pl-tool 执行，完整完成结果与简洁模型摘要分开，Turn 结束使用注册授权的 ToolControl。不保留旧 StaticTool 入口。

TodoUpdateTool 使用 Thread 的不透明扩展快照，工具自身校验 checklist 并生成 payload/context/CAS 变更；相同内容不写新扩展版本，不加入 call ID 或时间。保存格式不兼容时明确拒绝覆盖。不保留旧 TodoListTool。

新 session note 工具从 Thread 扩展快照读取原始笔记，读取/搜索复用纯内容逻辑，写入/patch 返回 CAS 候选。正文保留原始换行和 Unicode，不自动进入上下文；写入回执使用 Thread 扩展水位给出实际候选版本。不保留旧 working set 接入。

ColdStore.flush 显式接收 Thread ID 和已受理 commit 序号。SQLite 将该不可变记录映射到 writer 的受理水位，等待该记录而非刷新瞬间的全局尾部；已持久化记录不受其他 Thread 的新增队列或失败影响。

pl-trace 汇总已验证日志中的真实 ModelUsage，取消/失败/拒绝响应发生的消耗也计入，Running 不重复计费。缓存读写独立汇总但不再加到输入总量；缺失或计数溢出保持未知，输入估算不参与真实 usage 汇总。

Thread 提供不持有执行权的快照订阅；通知允许合并，中间事实通过 commit_sequence 和有界 journal_page 补齐。订阅取消或丢弃不取消 Thread，关闭后的最终快照可在通道结束前读取。完整日志仍是重放依据。

新 ask-user 工具返回 AwaitInteraction 和不透明问题载荷，core 分配与原调用绑定的交互 ID，并与工具结果一起提交 Pending。该工具必须独占模型批次并具备注册授权；Turn 返回 WaitingInteraction，回答通过显式 resolve 提交后才能继续模型步骤。

交互取消通过携带预期版本的显式命令执行，Pending → Cancelled 与低权限的取消上下文在同一 commit 生效，不构造空回答或业务扩展变更。重复提交同一取消命令返回原终态，不增加版本或上下文；过期命令和已经回答的交互拒绝取消。历史重放恢复当时已提交的取消说明。

模型和工具执行期间，Thread owner 仍受理消息及历史读取。消息进入同一个 owner 的收件箱并提交，但不改变已冻结请求或当前上下文；只能在后续请求准入时消费。该通道有界，不持有另一份 Thread 状态，也不能绕过关闭受理门禁。修改上下文、交互回答及执行命令继续按执行边界串行处理。

Studio 的物理模型会话身份包含模型、适配器、传输配置与账号/部署隔离摘要；显示名称变化不重建会话。绑定切换先关闭旧实例，成功后才替换；关闭失败或切换等待被取消时保留原 owner。Thread 关闭先封闭模型重新绑定，另一 Thread 的资源不受影响。该执行身份不直接充当 provider cache key。

provider 私有历史是否可消费由 model 校验，并在实际请求入口执行，不能依赖 core 调用方预先检查。core 不根据 Responses 原生记录类型选择或拒绝 provider。文本摘要的请求构造与响应校验归 model；core 只接收摘要结果并按宿主选定的替换策略提交历史。

取消或超时后迟到的摘要不产生上下文替换；压缩等待执行与私有会话关闭收束，再以失败事实返回已观察用量。成功响应不能绕过取消水位。

通用压缩配置仅表达 TextSummary 或 PreferNative，观测结果仅表达 Local 或 Native；OpenAI 的压缩配置值由 Studio 在装配时映射，具体 native 协议版本不进入 core 公共配置。

原生压缩能力接收冻结的模型请求，model 选择实际协议版本并验证唯一 checkpoint，连同实际 accounting 返回。core 不构造原生压缩模式参数、不检查加密内容类型，也不从返回数组中挑选 provider checkpoint；历史保留策略只组合已验证的替换材料。

文本 token 启发式由 model 提供并明确只属于近似估算。遇到媒体、加密 checkpoint 或无法确定 token 语义的原生材料时返回未知，core 不解析其字符串来补数。未知估算不单独触发容量压缩，仍可依据 provider 已报告输入量或显式压缩请求执行。压缩前后计数在产品协议中允许未知，不回填零或压缩前估算。

缓存诊断的 provider、schema 和请求指纹由 model 计算，输入接收不可变上下文摘要及上次诊断快照，不读取或修改 AgentSession。core 将返回的新诊断记录纳入正常提交。指令 section ID 对 model 不透明；具体业务变化原因由产品投影解释，model 只报告固定前缀变化。

删除 CoreRuntimeProfile 聚合入口；Studio 在装配时显式提供工作区执行绑定、Turn 参数、压缩策略和附件服务。引擎不再接受包含产品 Plan 默认策略的 Profile，也不保留旧入口的兼容转发。工具状态始终来自已经装配的 Thread 运行态。

ResolvedModelRoute 的模型构造和 reasoning 参数解释集中在 model。旧引擎构造入口接收已经构造的模型运行时及冻结调用参数，不接受路由或创建 provider 客户端；主循环与压缩共享同一份已解释参数，避免各处分别解释 reasoning effort。

动态工具替换由同一 Thread owner 在长调用等待期间受理；已经冻结的请求和已经启动的 executor 租约不变，后续步骤使用替换后的目录。关闭门禁同时封闭该注册入口。注册失败不改变当前目录，替换不关闭仍被在途调用持有的资源。

工具失败允许同时返回已经观察到的完整 payload/context。core 保存实际结果及失败事实，但不应用失败结果中的状态更新、交互或 Turn 控制。exec 的输出归档由工具侧注入的服务负责，归档成功返回稳定资源引用；失败仍保留执行事实和原始捕获位置，不把未归档内容伪装成可重放资源。

Studio 的文件资源库按完整字节摘要寻址。写入先复制到同目录临时文件并同步，再以不覆盖已有对象的方式发布；相同内容复用已有对象，冲突对象必须校验而不能静默覆盖。资源引用自身携带长度、摘要和媒体类型，读取可据此恢复，不建立具体工具结果表。本地命令归档只读取已排空的本地 capture；远程 capture 必须由对应远程读取适配器处理，不能交给本地文件读取。

远程 helper 协议 v5 提供有界文件范围读取与显式文件写入模式。归档客户端逐段核对偏移、总长度及实际返回字节数，拒绝截断或长度变化，逐段写入本地暂存文件后再发布资源。单帧上限不能变成完整输出的截断上限；失败保留远程源 capture，重试只读取输出、不重新执行命令。

真实模型的 Thread adapter 实现 core Model/ModelSession 端口。工具声明格式及 assistant 历史帧由 model 编解码；assistant 帧保存当时的 provider 调用名称、原始参数和原生材料，后续工具结果根据旧帧配对，不用当前目录重写历史名称。非 assistant 来源不能提交 assistant 帧，未知帧版本阻止新调用但不修改已有历史。

模型准备先完成 native/custom 工具投影与能力校验，再冻结估算及执行请求。custom 工具的 function-fallback 包装属于模型协议，model 解包为原始文本交给工具；历史仍保留当时真实 wire 参数。无法解包的模型输出作为被拒绝的尝试保存，不路由到可执行工具。

StudioThreadAssembler 使用同一入口装配新建与恢复 Thread，并登记准备中及已发布句柄。准备中的句柄不对外查询发布；装配失败或调用方取消时仍由登记表保有已创建 owner。关闭成功才删除登记，关闭失败保留重试入口；整体关闭先封闭装配，再等待准备收束，按产品父子关系从子到父关闭。

普通 Resource 上下文只表达资源引用；实际嵌入媒体由 model 的无角色 attachment 投影显式表达，避免完整日志被自动展开。准备阶段按冻结的媒体声明检查数量、字节、媒体类型和图片尺寸，通过 ResourceAccess 读取并校验，再生成确定性编码。工具媒体在完整工具结果批次之后进入 provider 输入，不能中断调用配对或提升为 system。

Thread 工具执行具有独立任务事实：开始前记录 Running，真实结果与任务终态在同一 commit 成立。任务记录只拥有调用关联与状态，完整业务数据引用同次交付记录。冷恢复把遗留 Running 收束为 Interrupted，不重新执行工具；模型上下文版本不因单独的任务状态记录而变化。

任务取消通过 owner 命令提交一次取消意图，再请求对应执行 token 取消。Requested 回执不表示物理执行结束；任务继续保持 Running，直到执行与资源清理返回。重复取消不重复提交，终态不可被取消命令改写；取消单个任务不取消其父 Turn。

普通工具的默认交付窗口为一秒；窗口内完成直接提交，超过窗口提交关联原调用的任务回执，执行 future 留在 Thread。后台结果与任务终态、收件箱消息一同提交，模型只在后续请求准入时消费；回执和最终业务结果是不同事实。具有独占控制权限的工具保持前台执行，不能在 Turn 结束后迟到地触发交互或结束控制。

工具任务访问能力使用当前 Thread 的只读快照和弱命令句柄。查询不改变状态；等待与取消分别需要注册授权，且只在调用任务仍运行时有效。wait 外观只返回就绪状态，完整后台结果由后续模型准入统一消费，避免重复交付或提前推进收件箱水位。

工具执行完成后若提交失败，Thread 保留原始完成对象与 executor 租约，禁止新的模型准入，并提供只重试提交的入口。失败提交不发布部分扩展、结果或任务终态；重试不再次执行工具。关闭必须先完成遗留结果提交，失败时保留 owner，不能仅记录日志后丢弃结果。

Studio 的标准工具装配使用 pl-tool 提供的稳定声明与工具构造器，由 model 编码声明后注册到 Thread。exec 的本地和远程装配分别绑定匹配的命令后端及归档服务；控制、todo、笔记和交互声明不含会话 ID 或运行状态。标准目录只是创建时的组合入口，不维护第二份运行注册表。

exec 和 write_stdin 在同一次装配中共享 Thread 私有进程管理器。write_stdin 通过任务能力验证目标是本 Thread 的活跃 exec 调用，再映射到内部进程身份；它不触发新命令，也不将尚未完成的 capture 归档为最终输出。需要即时串行执行但不改变框架状态的工具可显式声明前台调度，不因此获得结束或审批权限。

标准文件工具通过冻结的 WorkspaceFileBackend 执行；read/list 复用原有分页投影，patch 复用匹配与写入实现并以前台方式提交。历史保存当时的完整结果及实际模型预览，恢复不重新读取文件。装配入口同时绑定标准目录和匹配资源服务，再交给 StudioThreadAssembler 完成唯一 owner 发布。

新建 Thread 的初始上下文由 Studio 显式提供，并在发布 owner 前提交；上下文需通过通用调用配对校验。恢复历史和非空初始上下文不能同时传入，防止使用当前工作区、Skill 或配置覆盖旧内容。新配置生效必须在恢复发布后作为显式上下文更新提交。

冻结 executor 不等于永久授权：准备结束准入前复核原 ToolPlan 的权限仍有效，工具真正启动前再次检查。撤销或删除阻止尚未启动的副作用，已启动执行仍保存事实；迟到结果不得应用已经撤销的框架控制权限。仅 executor 重连及新增其他工具不撤销原调用。

模型切换是 Thread owner 的串行命令，接收通用模型工厂。旧会话关闭成功后清空私有接续及旧重试计划，再创建新会话；工厂失败时 Thread 明确显示模型不可用，保留历史并允许重新装配，不复用已关闭的旧会话。执行中的 Turn 不被参数刷新中途替换，后台工具任务与模型切换互相独立。

工具失败附带的 observed output 在内存完成对象中保留供提交重试，持久历史只在交付记录保存一次；错误诊断不复制完整业务载荷。错误源链作为诊断文本保存，检测重复源并限制异常链深度，明确标记截断，不影响业务载荷和实际模型上下文的无损记录。

core 的工具结果按事实提交顺序保存，model 对完整调用批次按原 assistant 调用顺序进行确定性协议投影。投影只重排同批次的结果，不更改载荷、结果关联或 core 历史；工具媒体同样按调用顺序排列，并放在完整结果批次之后。缺失和重复结果明确拒绝。

现役子代理工具的 schema、参数解析、历史分页和通知源属于 pl-tool，调用协调宿主提供的端口；core 不再包含具体 collaboration 工具模块。目录和工具共用宿主目标选择策略，不能让历史驻留判断反向依赖具体工具实现。

标准文件装配接收冻结的 ToolWorkspace，沿用只读及 writablePaths 策略、工作区写锁和 LSP 通知。命令执行的授权独立于文件访问授权，不能用 exec 的外部路径权限隐式放开文件工具；远程文件后端同样应用宿主传入的写入策略。

宿主辅助命令的超时也必须经过物理收束。本地使用统一进程组/Job Object 包装，同时等待退出与两路输出；远程保留原 exit receiver 和输出读取 future，发送终止后继续等待。终止请求失败不能伪装成执行已结束，退出或排空失败保留明确诊断。

物理路径校验、符号链接/reparse point 检查、安全目录删除和工具路径策略归 pl-tool::workspace。core 不导出具体路径安全实现；Studio 的工作区、技能和资源清理消费工具层接口。移动不改变现有平台行为，原有路径边界回归随实现迁移。

AgentWorkspace 的路径、文件可写策略和平台边界由 pl-tool 拥有。物理宿主指纹与工作区组合绑定由 Studio 每 Thread 资源持有，core 不携带或返回物理工作区。每轮配置核对读取同一份 Studio 冻结绑定，不重建工具实例。

产品附件宿主接口归 pl-tool，Studio 注入持久化与读取实现。准备媒体只在 model/Studio 适配边界传递，core 不持有 MaterializedAttachment；新 Thread 继续通过通用 ResourceReference 和 model 投影承载媒体。

媒体准备使用工作区已有的 image 0.25（PNG/JPEG/WebP/GIF feature）与 base64 0.22，许可均为 MIT OR Apache-2.0；没有引入新版本或新编解码格式。它们只在 model 适配实现中使用，不进入 core 公共类型；独立 model 构建新增相应解码/编码依赖成本，完整 Studio 工作区原本已使用这些依赖。

附件 writer 的唯一契约是有序原子批量写入；单图写入也经过同一接口。工具层不提供逐图循环冒充批次提交的兼容构造，MCP 图片准入只判断实际媒体能力。

SQLite 后端初始化失败时显式关闭探测连接，关闭失败保留组合错误。正常 shutdown 在 writer 排空并退出后关闭整个连接池，成功后才释放数据库文件锁；仍存在的 repository clone 不能继续读取旧连接。

旧格式协调重置仅从持有 Studio 独占运行锁的启动入口进入。先校验两个数据库版本与完整性，再将数据库完整快照备份到私有目录；可恢复标记依次记录备份完成、旧会话库归档、产品关联就绪和新会话库就绪。标记存在时禁止产品发布，重启继续同一操作。只清理已知会话表与会话投影，保留项目、配置、SSH 凭据、附件文件、worktree 与未知产品对象；未来版本、损坏数据库和不明 WAL 均明确失败。独立 StudioStore/core 打开不隐式执行此重置。

协调重置开始后由专用启动任务持有独占运行锁，调用方取消等待不会释放锁或中断 marker/备份文件操作。任务完成后转交锁给运行时；失败保留恢复标记，释放锁供下一次启动继续。

provider 前缀缓存分组键不包含 temperature 或 max output tokens：这些是生成参数，不是已有输入前缀的内容。模型、账号/部署隔离、协议、指令、声明和会影响编码的选项继续参与分组；参数改变仍体现在实际执行请求与用量记录中。

core 公共 API 不镜像导出 provider 目录、凭据描述、hosted search 能力或 MCP 服务目录 DTO。Studio 配置目录直接消费 model 构造的产品协议 DTO；这些产品查询不会经过 Thread 框架接口。

SQLite 的具体 ORM 错误只在后端内部构造与转换，对外以标准 Error source 承载；不重导出 ORM 类型。上层可报告完整错误链，无需导入 sea-orm 或检查 ORM 变体。

Thread 输入队列保存调用方提供的稳定输入 ID、完整动态载荷与已经冻结的通用上下文投影。受理和模型准入是不同提交：受理即返回幂等回执；只有模型准备完成、权限与容量复核通过后，消费状态才与实际请求记录及用户上下文同一提交。准备失败或准入前取消保留待处理输入。队列由 Thread 按受理顺序选择，上层只发出执行驱动请求，不另建队列。冷恢复恢复待处理事实但不主动执行；上层装配完成后显式驱动下一输入。被驱动的执行尝试使用独立 Turn/attempt 身份，因此失败准备后可以用新尝试继续同一输入。

持续执行输入队列的驱动同样属于 Thread actor。Studio 显式启用驱动并传入通用步骤上限，之后 actor 串行处理已受理输入；产品层不为每个输入生成旁路执行任务。普通 owner 命令在下一轮驱动前处理，模型与工具配置可在 Turn 边界生效。执行失败、交互暂停或步骤上限停止驱动，避免自动重复有费用的请求；新输入的受理本身不解除暂停，宿主必须明确继续。驱动状态只描述物理执行，不在冷恢复时自动激活。

MCP 动态工具绑定固定服务租约与声明，执行器解析自身参数后调用同一租约。结果中的图片、音频和嵌入 blob 按精确字节归档为稳定资源引用，业务结果保留其余结构与元数据；模型媒体投影由 Studio 注入 model 能力，生成当次实际上下文。归档或投影失败须保存原始已观察结果，不重新调用远端工具。服务 annotations 和任意 JSON 字段不授予 core 控制权限。

MCP 归档失败使用显式 `pl.tool.mcp-unarchived` 结果格式保留收到的完整协议材料，包括尚未成功归档的 base64 字符串；它不伪造资源引用，也不声称已具备正常媒体投影。模型仅收到失败说明，历史仍可查看原始材料。后续修复或升级产生新记录，不能重放远端副作用或改写旧结果。

MCP 资源目录、模板和读取 façade 与服务工具使用同一冻结租约。资源查询只路由到该租约声明支持 resources 的服务；未指定服务时按稳定服务顺序聚合。读取结果保留完整返回信封和元数据，嵌入二进制转换为持久资源引用，读取失败或归档失败不产生默认空结果。

prepared call 可携带 model 编码的工具投影材料；core 不解释其格式，随请求准入冻结并保存，原样传给该请求产生的工具调用。工具不能读取全局可变模型目录来重新推测已受理请求的能力。缺少图片能力时保存原始资源并交付资源引用；具备能力时按冻结限制准备实际模型图片，历史保存当时的资源与投影。

文件写入的参数解析、路径授权、写锁和 LSP 通知由工具实例负责。静态产品入口与 Thread 动态入口消费同一写入实现；动态入口传递通用取消能力，成功结果冻结实际路径、写入模式与字节数，失败不推断写入已回滚。core 不持有工作区或写文件参数类型。

文件写入模式贯穿工具参数、工作区后端与 helper 协议。create 使用排他创建，append 使用追加文件句柄，overwrite 使用原子替换；远端不以读取旧内容后覆盖的方式模拟追加。helper 协议升级时两侧版本同步，不保留旧 WriteAtomic 请求转发。所有写入都在冻结工作区路径校验之后执行。

工作区文件原子覆盖保留已有目标的文件权限，新文件采用普通文件创建权限并遵守 umask；配置和私有元数据写入继续使用独立的私有权限策略。

helper 的写入模式回归复用工作区现有 pretty_assertions，仅增加测试依赖（MIT OR Apache-2.0）；不引入新依赖版本，不影响生产 helper API 或运行时体积。

model 保存完整的归一化响应，而非仅保留正文与调用列表；响应 ID、返回的模型标识、用量、定价、编排指标及时间信息同属不可变回执。回执同时记录请求模型、provider 实例、协议及脱敏隔离身份，产品层通过 model 的解码接口读取，不让 core 理解这些字段。用途只是诊断分类，不改变工具权限或调度。

工具授权身份与模型声明、executor 实例分离。宿主通过类型化注册接口提供不含凭据的策略身份，权限策略变化时更换；core 只比较身份，不解析策略。更换身份阻止旧计划准入、旧调用启动及旧任务取消权限继续使用，但不改变模型声明或缓存前缀。工作区工具从冻结的目录与可写策略确定授权身份。

工具媒体归档与 model 投影使用统一的工具层端口，MCP 与文件图片读取共享该端口，不互相依赖。view_image 从冻结工作区后端读取原始字节，按 prepared call 的图片能力规范化；原始图片和模型读取的变体均有持久资源保证，历史直接保存当时的上下文。

LSP 工具通过冻结的本地或远程路径绑定访问服务。查询参数与结果由 pl-tool 解析和投影；core 只保存动态载荷及实际上下文。远程查询的路径校验通过对应 helper，不能借用宿主本地文件系统判断远程路径。工具关闭只释放引用，共享 LSP 服务由 Studio 生命周期统一关闭。

LSP registry 接收宿主已经解析的工作区身份，不对该路径再次执行本地 canonicalize。登记一个工作区不隐式淘汰其他工作区；关闭与回收必须由拥有租约的 Studio 生命周期明确驱动。

Skill 目录与读取工具绑定冻结 catalog；列表不携带当前会话或时间戳，技能正文与支持文件只在实际读取时进入工具上下文。读取快照作为工具拥有的不透明扩展保存，相同快照不更新扩展版本；重放不再读取当前 Skill 文件。目录和资源加载继续校验 provider 身份、版本与调用许可。

项目 Skill 管理将文件操作结果编码留在工具层，同一本地实现用于静态产品入口与动态 Thread 工具。管理操作持有工作区写入租约，阻塞文件 IO 隔离执行；发生错误也使目录缓存失效，以涵盖部分写入。远程或只读目录不会通过本地管理装配入口隐式获得写能力。

工具需要对话背景时，读取产生本次调用的模型请求快照，而不是可变会话或尚未准入的消息。该快照只读且不持有 Thread owner。独立搜索由 pl-tool 筛选近期用户/助手文本，排除指令、运行时注入、工具结果和 provider 不透明材料，并冻结完整搜索响应与实际模型正文。

搜索协议已经直接派生 schemars schema，因此 pl-protocol 显式声明工作区现有 schemars 依赖（MIT）；没有增加新版本。Schema 在工具声明边界使用，core 不消费搜索参数类型。

provider 托管能力由 model 参数装配，不构造会被 core 本地执行的占位工具。产品中的旧引擎装配包装归 Studio，独立搜索执行器留在 pl-tool。托管声明与本地工具名称冲突在模型准备阶段拒绝，避免请求和调用路由含糊。

托管工具由 model 工厂参数提供，准备时与本地声明合并并验证名称冲突，不进入 core executor 注册表。prepared call 同时给出不透明请求元数据，记录实际规范化声明、绑定与生成参数；core 将它与请求准入一同提交，即使调用失败也保留当时参数，不按当前配置重建。

模型失败可附带 producer 编码的不透明诊断事实。model 在转换错误时保存原始计费快照和冻结绑定，core 不解释定价字段，随失败尝试保存并原样恢复；无法编码标准回执时使用显式诊断格式，不伪造零费用。

子代理查询、停止与关闭通过 pl-tool 的类型化宿主端口进入 Studio。caller 来自 core 分配的调用身份，不从工具参数读取；Studio 校验所属树和后代关系，拒绝跨树控制与自关闭。core 保留通用 Thread 操作，不拥有产品 Agent 目录或协调政策。

宿主可显式要求消息唤醒 Thread。唤醒水位与消息受理一同提交；活动 Turn 若已消费该消息，结束后不再额外调用模型。未消费消息在空闲时通过运行时上下文启动执行，不伪造用户输入；冷恢复保留唤醒事实但仍需宿主明确恢复驱动。

子 Thread 继承上下文时保留原始记录与已交付内容，只裁剪到完整工具调用批次边界；不执行旧工具、不重渲染正文，也不继承可变模型会话。指令是否继承由宿主显式选择。新执行必须同时检查历史上下文中的调用与记录身份，避免继承或显式重建后复用旧 ID 破坏重放。

子代理创建通过 Studio 子 Thread 工厂解析 Profile、配额与资源绑定，工厂必须校验 caller 的创建权限。工具只提供类型化创建请求和 core 分配的冻结调用上下文。装配器重新校验父节点仍可受理，再创建独立模型会话与工具，按宿主选择继承对话；首次任务作为父来源消息提交，避免提升为用户指令。

Studio 从同一配置快照解析启用 Profile 与模型路由，返回显式的创建参数；Profile 文件扫描不持有配置锁，也不把临时路由写回配置。旧产品入口与新的子 Thread 工厂共用这一解析边界，避免 Profile 和 provider 参数来自不同配置修订。

Git 动态工具复用工具层的命令验证、凭据注入与脱敏管道。宿主显式提供工作区配置、后端、凭据服务及授权身份；声明不携带凭据或运行状态。结果正文与完整工具层数据分别冻结，Git 的 provider/执行策略不进入 core。

Git 非零退出保留工具层的结构化观察结果（退出码和脱敏后的两路输出），通过类型化失败传给 Thread。错误诊断只描述失败阶段，不再次复制完整输出；实际载荷和模型预览仍由同一提交保存。

工作区路径查询由 tool 后端返回显式存在性；不存在与权限、边界、传输错误不可混淆。Thread 的 `stat_path` 保存执行时元数据和实际上下文，本地与远程使用同一动态工具，core 不解释文件字段。

Studio 的 helper 资产装配由产品资源模块统一提供。新 Thread 本地命令后端同样持有可执行映像租约，嵌入式发布不依赖 PATH；关闭其他 Thread 不会使在途 executor 的 worker 路径失效。

Thread 标准工具装配显式接收同一配置快照中的能力开关。关闭的能力不创建 executor、不获取 worker 资产；后续 Git、MCP、LSP、Skill 装配遵守相同快照，不能通过可选 builder 方法重新启用。配置更新由宿主形成下一份目录后原子替换，不修改旧 executor。

子任务创建保留 none/all/最近 N 个用户回合的历史选择，以及目录写入范围和业务 metadata。tool 解析输入，Studio 验证 Profile 与工作区模式，资源宿主验证实际目录；这些字段不进入 core 调度类型。

Studio 在子任务资源准备前预留身份和树内名额，准备中的任务同样受产品深度/数量限制。预留持有独立取消令牌，关闭宿主先取消准备任务并等待预留释放，再关闭已发布 Thread；准备失败不得留下名额。现役默认策略保持仅 root 创建子任务、每树最多 16 个 Thread。

物理 workspace 准备是 Studio 的产品资源职责，输入为项目、根/子 Thread 身份、Profile 工作区模式与写入范围，不再要求旧 Agent 执行快照。现役生命周期与新 Thread 创建流程消费同一资源准备实现；Git worktree 租约仍先记录准备事实，再执行创建及失败收束。

子任务工厂必须提供未发布资源的幂等回收端口。Studio 在调用工厂前登记资源 owner；准备、装配或取消失败时先关闭已建立的 core Thread，再回收未发布产品资源。回收失败保留 owner、父子关联及重试入口，不能仅释放创建名额后丢失资源。模型输入开始受理前完成发布交接。

Studio 新建 Thread 的种子明确区分模型上下文与不透明扩展记录：Profile 指令与选定工作区说明进入上下文，创建 metadata 和完整工作区 receipt 保存为扩展载荷。冷恢复不能同时提供新建种子，避免当前配置覆盖历史事实。子任务资源工厂消费已解析配置快照，装配实际本地/SSH 文件、命令、Git、MCP、Skill、LSP 服务及共享冷存储；这些参数不进入 core 的业务类型。

Studio 搜索计划统一投影到 Thread：standalone 搜索创建 pl-tool executor，hosted 搜索只配置 pl-model 能力，不向 core 注册占位 executor。exclusive 搜索装配只包含选中的搜索能力；不会先创建被隐藏的 workspace 工具。托管搜索选项由同一产品映射生成，保留缓存/索引/实时模式、域名和位置配置。

工具执行前可绑定宿主 ExecutionPolicy。core 通过类型化成功/失败决定是否调用 executor，不解析审批 JSON；等待结束后再次校验原 executor 的权限租约和任务存活状态。策略实例身份与模型声明分离，策略变更撤销旧待执行调用，重连复用同一策略租约时不改写模型输入。

执行许可是独立的框架事实：请求绑定当前 task/call/tool/turn，提示正文仍为不透明载荷。宿主通过 revision 校验的 Allow/Deny 命令回应；core 不解码正文中的 approved 字段。许可只在同一活跃 executor 权限租约内有效，取消、权限替换或冷恢复不能复用旧许可；重放保留提示与决策事实，不触发审批服务或工具。

执行策略返回调用级 ExecutionGrant；能力名由上层定义，core 不解释。工具仅消费可信 CallContext 中的授权能力，不读取模型参数中的授权标记。授权仅对当前调用有效，不进入模型声明、不从冷历史恢复；物理 confinement 仍是工具后端不可被授权放宽的边界。

文件后端按调用级授权创建临时访问视图，保持原 workspace 根、写入范围与服务租约；不修改 Thread 工具实例的默认边界。仅本地 host-permitted 工作区可消费外部路径能力，受限 worktree、远程和容器默认不提供放宽视图。授权结束后下次调用恢复默认边界。

审批产品 DTO 直接投影 core 保存的许可请求、决定、时间与原样响应载荷。UI 响应通过 Studio 解码后提交 revision 校验的类型化命令，产品交互服务不另存许可状态。未知审批载荷格式投影为原始记录，不能呈现为可执行的审批控件；提交决定时仍要求可识别的审批协议。

物理工具装配接收 Thread 身份、配置快照、模型绑定、项目与资源，不依赖子任务 Profile 类型，供 root/child/恢复共同使用。新 Thread 继承上下文时，保留的旧指令和新稳定指令先于对话历史，运行时事实随后追加；不能把 Profile 指令放到历史尾部冒充 adapter 的尾部指令更新能力。

root 与 child 初始指令由同一创建期捕获流程生成：复用已选中的远程文件服务和执行环境，保存配置/角色/项目文档来源快照，同时保存实际投影的通用上下文。动态 Skill 推荐不进入这份稳定前缀。root 冷恢复装入通用 journal，不调用指令捕获器，不用当前文档重写过去。

Workflow 的计算与工具外观属于 Studio。动态 workflow 工具从冻结 CallContext 读取 `studio.workflow` 扩展，独立计算候选状态，通过扩展 CAS 与本次实际工具正文一起提交；拒绝或冲突不改变状态。未知载荷版本及与当前注册图不匹配的状态不能默认为空状态，也不能由新图重新渲染历史结果。

Plan 工具采用产品状态编码与通用扩展 CAS。plan_submit 在同一个工具提交中保存完整计划状态、实际模型输出和不透明确认问题；确认问题身份由 core 调用关联提供，不能由模型自行指定。用户确认的解释与状态机决策属于 Studio，后续通过通用交互解析提交计划状态更新。

交互解析可以携带一条通用 continuation 输入。core 在同一候选状态内校验响应、扩展 CAS、上下文投影和输入身份，再一次性提交；重复提交只返回相同回执，不重复入队。存储压力不阻止已受理交互的事实收束，续跑仍经过正常执行准入。

Studio 的 Plan 确认入口核对冻结问题、Plan 内容摘要、计划 revision 与 pending interaction 身份，使用产品状态机解释回答；随后将回答投影、Plan 扩展更新与带 presentation 元数据的完整后续输入交给 core 原子提交。重复回答返回原投影，不重新推动输入驱动器。

Studio 对外交互 ID 包含 Thread 与 core 本地交互身份的无歧义编码。Rust 产品入口解析并核对 owner，客户端只透传 opaque ID；provider 在不同 Thread 中重用调用 ID 不会造成回答串路。core 不依赖这种产品 wire 编码。

普通用户提问、Plan 确认和执行许可共用 Studio 类型化交互路由。路由从 core snapshot 读取事实，不建立另一套可写交互状态；用户回答作为一次原子响应与隐藏续接输入提交，模型只接收保存时确定的内容。跨 Thread 复用本地调用 ID 仍通过产品 wire 身份准确路由。

工程验证中的 workflow 参数校验由 xtask 直接调用 Studio 的产品校验入口。该 workspace 内部依赖使用同仓库维护与许可边界，确保验证消费实际业务规则；不增加第三方依赖，也不恢复 core 的产品 API 导出。

StudioThreadFactory 是独立的产品装配边界，只持配置与共享服务租约，不持旧 session、TurnEngine 或交互 waiter。StudioRuntime 构造时一次安装同一工厂的子任务创建端口；root/child/恢复工具实例仍由 core Thread 独占。Mode 与模型能力的兼容判断属于 Studio Mode 模块。

激活先登记准备 owner，再创建物理服务与 core Thread。并发等待者共享准备结果；取消等待者不丢失准备 owner，关闭会取消并等待仍在准备的任务。冷 child 从保存的 workspace/project 绑定创建新实例，不能重新创建 worktree 或重演历史副作用；其父 Thread 必须先激活。

产品交互读取和回答走新 Thread owner：冷读取仅重放 journal，回答前按保存的父子顺序激活所需 Thread。root 协作工具由显式曝光策略装配，exclusive 搜索不会意外获得协作工具。旧交互 waiter 不再是产品回答入口的状态来源。

输入受理由 core 原子选择 Start/Steer/Queue。steer 记录原目标 Turn，在下一份模型请求冻结时按序加入用户上下文，并与该请求一同提交消费事实；冻结后到达的 steer 留待后续请求。未消费的 steer 与其他输入一样保留，可在中断恢复后继续处理，不改写已执行请求。

产品提示词提交返回 inputId 和该输入首次受理的 commit 序号，不预先伪造 Turn ID。客户端通过同 ID 的输入时间线条目关联实际 Turn。附件在受理前保存并验证长度、摘要，完整业务元数据与实际模型上下文一同进入 Thread；草稿只在输入受理后提交。新建目录事实从热 owner 读取，不等待异步数据库跟随。

通用 commit 记录内存提交时间，异步数据库刷盘时间不能代替事实时间。Turn 保存启动它的输入身份，即使模型准备阶段失败也能关联回受理输入；InputRecord 提供已准入上下文记录的框架身份查询，产品投影不自行拼装 core 的内部记录 ID。

Turn DTO 和 Turn 时间线条目保留实际 inputId 关联。即使模型准备失败而输入尚未进入模型上下文，产品也能将失败对应到已受理输入；不需要复制一条从未交付模型的用户消息来伪造关联。Bridge 与 Dart 只消费这一类型化字段。

Turn 产品投影依据保存的状态、提交时间和实测耗时生成，不以数据库时间或当前时间替代。只有通用取消事实而没有发起者证据时显示 unspecified，不宣称由用户取消。model 失败回执保存 provider 的结构化错误、重试语义与原始消息，Studio 投影不从消息字符串猜测错误类别。

输入显示投影读取提交时保存的产品正文、附件元数据和 presentation，不把模型附件注释反向当成用户输入。通用文本片段直接拼接，保留原始空白；未知输入格式交由原始记录查看，不能默认为空文本。

模型正文投影读取已保存输出与 model 回执，保留文本分片的实际字节和推理正文。取消后返回或被 core 拒绝的输出显示对应非成功终态，不作为正常回复；不支持的模型内容明确暴露投影失败，不能静默变成空正文。

工具时间线从已提交模型调用恢复原参数，从任务/许可事实投影执行状态，从 delivery 读取实际交付内容。业务 payload 只作原始事实保存，不能被 UI 投影当作 exit code、审批或成功状态来源；未知上下文载荷以原始格式元数据保留。

产品时间线 ordinal 从原始 commit 内的输入、Turn、模型尝试和工具调用顺序统一分配；隐藏或暂时为空的投影保留槽位，后续正文出现或终态更新不能挤动已有条目。各投影的当前输出集合不作为历史排序的事实源。

只读日志句柄与执行 mailbox 分离。owner 在发布快照前发布对应不可变提交；观察者可按快照水位分页读取，即使执行 owner 已关闭也能读取最终事实。日志只共享不可变提交引用，外部不能写入。Studio 订阅直接从同一水位的快照和 journal 生成产品投影，投影失败沿订阅返回，不伪装正常流结束。

带预期 Turn 身份的中断由 Thread mailbox 在 owner 内核对并取消同一执行代次；产品不得先读取快照再取消一个可能已切换的 Turn。停止同时暂停输入驱动，不删除待处理输入，后续继续必须显式恢复。

Thread 关闭在模型与工具释放前收束全部待答通用交互，保留明确取消事实。归档必须等待整个 Thread 树关闭成功后才发布目录移除；失败保留 owner 与重试入口，不能通过日志警告后继续发布成功归档。

空闲重新配置使用 core 的单次事务：核对提交水位、拒绝活动 Turn/任务/输入/交互，暂存扩展和上下文替换，校验工具目录后一次发布。Studio Mode 切换只替换自身业务工具与已保存指令中的执行 Profile，不重新扫描历史工作区内容。Mode 身份与工作流同属扩展事实，产品目录为其投影。

Studio 初始化只审计并收束已保存 Thread journal，不启动旧 AgentRuntime，也不构造模型或工具。冷恢复遗留执行的通用提交通过 core 纯函数生成；SQLite 保存成功后，产品才完成初始化。实际模型和工具仍在显式激活时装配。

无法解释的上层历史内容投影为统一原始记录：保留每段format、version与原始字符串，界面以可选择的纯文本展示，不通过Markdown或JSON重新渲染原文。显示未知记录不授权继续执行；当前模型或业务状态缺少必要decoder时仍明确拒绝新执行。


### Studio 产品观察与协作查询

Studio 拥有 Thread 产品观察任务：按快照固定水位读取不可变 journal，投影 Agent/Thread 目录、显式进展和模型计费。计费使用回执中的冻结模型绑定、价格和用量，冷恢复以 inference identity 幂等重放；父级通知只处理观察注册后的新增事实，使用稳定消息 identity 防止失败重试重复送达。观察失败保留可重试状态，由同步屏障返回错误；关闭等待最终 commit 的投影、目录保存及计费保存完成。

Agent 查询仅允许读取自身或同树后代，不通过查询激活冷 Thread。会话及进展分页游标冻结 journal 水位；进展保留每次显式提交的完整 detail，超大单条以带字节位置的 UTF-8 JSON 分片继续读取，不能截断正文。Agent Profiles 来自 Studio 配置查询端口，工具不持有整个 StudioRuntime。子代理只拥有进展上报能力时，不因此获得创建其他代理的权限。

冷目录读取遇到未知 mode payload 保留已有目录元数据；只读历史展示原始载荷，真正激活仍严格校验所需 producer codec。

观察者更新产品目录时仅在目录 owner 的锁内修改运行状态和更新时间，不重写预先读取的完整 Thread。并发标题、Mode 与归档操作保持当前事实；已移出热目录的条目不被迟到观察结果重新插入。

Composer 只有仍持有非空 accepted input identity 时才消费对应 Turn 的提交结果；启动确认清除关联后，后续执行失败只留在时间线，不能把空 identity 相等误判为当前输入失败。

成功且具有已保存 EndTurn 控制的 complete 工具交付，通过生产者的版本化 decoder 将原 summary 投影为最终回复，并使用交付时固定的时间线位置。业务 payload 中的 completed 字符串不能独自生成完成状态；失败、取消或其他工具的同名格式不生成最终回复。

spawn_agent 回执携带子 Thread 装配时冻结的实际 workspace assignment（projectRoot、root、写入范围及 worktree 身份），来源是保留资源租约对应的 studio.workspace 扩展。成功和初始消息投递失败均保留该身份；发布前解码失败沿未发布 child 清理路径返回错误。无工作区的自定义装配可以省略该字段，不从调用参数猜测路径。

close_agent 的 workspaceDisposition 默认为 preserve，也可显式 cleanup。产品协调器在关闭前冻结整个目标子树的 disposition 并封闭新工作准入；关闭 Thread 和观察屏障后才释放已发布工作区资源，成功后才移除 owner。清理串行执行，失败保留原 disposition 与关闭中的 owner 供同策略重试，不能更改策略或恢复执行；普通宿主关闭默认保留工作区。实际 lease 身份校验、删除和保留由 Studio 工厂负责，core 不解释工作区策略。

已发布 child 的 close 默认保留工作区租约；显式 cleanup 在 Thread 与观察任务关闭后校验租约与实际 worktree 身份，记录 cleanup requested 再物理删除，成功才记 cleaned。校验或删除失败保留资源和可重试关闭记录，不吞掉错误。

工作区清理发生部分成功（目录已删除而分支删除失败）后，重试仍校验冻结路径和分支身份；目录不存在时跳过内容预览并继续幂等资源收束，不能因预览缺目录而永久阻断剩余分支清理。

Recovery 显式 cleanup 使用相同部分删除重试契约；恢复展示仍保留实际预览失败诊断，清理命令可在已校验目录缺失时继续收束残余分支。

启动逐 Thread 恢复审计先读取纯目录关联，再独立解码各自 journal；单条日志损坏产生该 Thread 的 CleanupThread 提示，不提前阻断同项目其他日志的恢复收束。

## 模型输出准入与有限纠正

模型输出先校验请求身份、上下文 revision、工具目录和调用身份，再校验 Solo 批次；整批准入成功前不执行任何工具。准入错误保留具体类型与拒绝的原始 attempt。只有 Solo 混批允许通用 Turn 循环追加框架纠正上下文后重新生成，每 Turn 最多两次，计入原有步骤预算；其他一致性错误不自动恢复。纠正以新 attempt 关联被拒绝 attempt，从 canonical 已提交历史准备，拒绝的 provider continuation 不成为已提交上下文。取消、关闭和持久化失败不能被纠正覆盖。

任务查询/等待/取消只接收本 Thread 回执的完整 taskId，未知任务返回 TaskNotFound，不猜测前缀或修改大小写，也不泄露其他 Thread 的任务。业务完成与 reviewer/测试充分性仍由 Studio Prompt 约束，不进入 core。

拒绝记录现在持久化原始输出与类型化原因，`pl.core.thread-commit` 升至格式版本 2；不双读旧版本。旧 journal 保留原始数据并明确报告版本不支持，不自动清空数据库。新验收使用隔离的新 Thread。
