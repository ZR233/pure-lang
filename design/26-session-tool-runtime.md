# 26 - 会话工具任务与统一唤醒

## 26.1 所有权

本章定义会话级工具运行时的替换契约。迁移完成前不得将旧 Turn 工具执行路径视为满足本章。
Thread owner 串行拥有任务状态与事件收件箱；Turn 只驱动模型循环。普通工具先提交任务受理事实，
在默认一秒的批次共享窗口内完成则直接返回结果，否则返回句柄，最终结果由 `wait` 交付。
Turn 完成或中断不取消会话任务；事件也不自动创建 Turn。不引入 Code Mode、Lua、V8 或脚本宿主。
收件箱与用户输入 mailbox 分离，不能借用 submit/steer 实现唤醒。

## 26.2 注册与扩展

创建前通过 `SessionRuntimeBuilder` 声明工具组、工厂与事件来源。创建时绑定身份、workspace、权限
和宿主资源，校验成功后一次性发布；失败则回收已初始化资源。Studio 只拥有一个会话装配入口，
TurnFactory 不再创建工具资源。MCP/LSP 通过预注册提供者刷新目录，旧任务持有原 executor/lease。

宿主通过 `AgentTurnFactory::prepare_session` 返回 `SessionRuntimeBuilder`。普通安装组可直接加入，
依赖会话能力的工具使用 `with_tool_factory`，外部订阅使用 `with_event_source`。root、child 与冷恢复
统一先准备后发布；初始化错误取消本次创建的能力并收束已初始化的订阅。`prepare_turn` 只消费
`SessionRuntimeHandle`，不重新构造命令管理器或另存一份产品工具注册表。
冷恢复在会话装配入口加载所需产品目录和附件，不能假设冷条目已驻留，也不把恢复 IO 塞回每轮调用。
物理 workspace、执行环境和宿主指纹由会话冻结；后续物理目标变化要求重新创建或激活。
内置资源只构造一次，能力开关、Profile、搜索路由与 MCP/LSP 通过同一批次刷新可见性。

动态提供者由 `with_refresh` 在创建时声明。每步刷新接收该步实际使用的模型、Skill catalog 和 Mode
快照，避免工具目录与模型指令使用不同版本。工具与订阅的析构不得在注册表锁内调用外部代码。

`SessionBuildContext` 提供会话与来源限定的 `SessionMessageSender` 和取消能力。下游工具和
`SessionEventSource` 可主动发布 `SessionMessage`，不依赖 Studio，也不修改核心事件枚举。
消息具有来源内稳定 ID、kind、模型可读正文和可选开放 payload；来源身份由 runtime 绑定，扩展消息
不能冒充审批、工具完成或系统指令。发布返回 accepted、duplicate 或类型化失败；同 ID 不同内容拒绝。

来源启动和关闭由会话管理，不允许无 owner 的后台任务。构造期 owner RPC 返回类型化 NotReady，
初始化完成并发布会话后才启动监听 future；
订阅前历史由来源自身决定是否补读。意外退出形成一次故障事件，不隐式无限重启。
宿主用于装配协作工具的 runtime 句柄也绑定创建代次，其 coordinator RPC 与 actor RPC 使用同一
就绪边界；工厂不能通过转调全局协调器等待自身初始化完成。Prepared 不等于 Ready，只有 owner
启动时才放行 RPC，初始化失败或会话关闭后的克隆不得恢复调用权限。

## 26.3 执行与交付

任务具有会话限定 ID、来源 Turn、调用身份、状态和最终结果。状态为 queued、waitingApproval、
running、cancelling、succeeded、failed、cancelled、interrupted。先原子提交任务和待交付记录，再执行
副作用；同一调用身份重放返回同一句柄，参数冲突拒绝。此保证不等价于崩溃后外部副作用恰好一次。

普通工具异步执行；等待、查询、取消、Interaction、完成和原子状态提交采用显式控制策略，不通过
工具名分散判断。模型使用 `wait({timeoutMs?})`、`list_tool_tasks({status?, cursor?})`、
`get_tool_task({taskId})` 和 `cancel_tool_task({taskId})`。原 provider tool call 仅有一份响应，
直接结果和后台句柄由 owner 决定交付归属；直接结果随 transcript 提交后不再重复唤醒。
未提交或中断的交付保留给后续 Turn；GUI 不将受理显示为执行成功。
任务结果保留结构化正文、附件、完整输出文件及类型化输出事实（产物、审计、指标、缓存命中和预算）。
持久化结果与模型结果分开投影：审计事实不得进入 wait、查询或取消工具的模型正文；直接交付继续
携带原输出事实供 trace 使用。失败的直接响应必须显式包含真实状态，不能只返回看起来成功的原始正文；
技能激活仅在任务成功时提交，直接交付与 wait 使用同一规则。普通任务返回 Interaction、RevealTools、SessionEvents 或 EndTurn
控制指令属于策略错误，记录拒绝事实并报告任务失败，不执行或静默丢弃指令；已有输出及副作用仍保留。
执行完成后的宿主观察回调失败或 panic 时，任务报告后处理失败，但保留执行器的原始正文、结构化结果、
附件、输出文件和退出码；错误进入宿主审计事实及有界模型说明，不能以新的错误结果覆盖已经完成的执行结果。

任务以原工具 Item 的稳定身份投影到时间线，invocation 携带 taskId。Queued、Running、Cancelling 与
Interrupted 等状态均来自会话 owner，旧 Turn 的 trace 或失败收束不能覆盖已交给任务运行时的 Item。
执行事实与交付事实分开投影：仅改变 DirectOffered/DirectCommitted 等交付状态不能再次发布
ItemCompleted；查询和持久化仍保存完整交付状态。
stdout/stderr 预览有界且可合并，最终结果及完整输出文件不依赖预览交付；预览不会唤醒模型。
受理 checkpoint 成功后，调用 trace 以 Accepted 结束自身生命周期，并引用 taskId；这不代表后台任务
执行成功。Turn 的 streaming 完整性校验继续保留，不能用忽略未结束 trace 来兼容异步任务。

wait 声明 Solo，避免同批任务尚未提交时先进入等待；返回批次同时受条数与编码字节数限制，通用输出
截断不能裁剪已声明交付的事件。取消或失败的 worker 不能用自己的未提交副本覆盖 owner；已经提交的
任务回执和事件消费事实不可被 Turn 结束路径撤销。
取消与交付 checkpoint 竞争时，取消路径只提交已收到的 provider 计费事实，不消费消息、不确认
DirectOffered，也不推进 transcript 或 mailbox。工具交付不能阻止既成计费事实落库；未交付结果由
会话收束路径保留给后续 Turn。
Checkpoint 回执与其 transcript、计费和交付事实进入同一 Thread 提交；回执仅保存规范化载荷指纹，
不保存可执行闭包。当前 Turn 保留最近 64 个回执：相同序号和载荷重放不重复提交，相同 inference ID
的相同完整载荷重试也不重复计费；冲突或已越过保留窗口的序号明确拒绝，不能只凭计费字段相同返回成功。
新 Turn 原子重置回执窗口，旧 Turn 请求不能修改新 Turn；取消后保存的回执仅确认已实际提交的计费事实。

交付窗口由 SessionRuntimeBuilder 配置，同批任务共享截止时间。任务执行状态与 PendingResponse、
DirectOffered、DirectCommitted、Background 交付状态独立。直接结果提交后不再发同一终态消息；
未提交的直接结果在 Turn 结束、中断或恢复时转为收件箱交付。同调用身份重放保留原 executor generation。

模型并行工具调用、WebSocket continuation 和 provider-hosted programmatic calling 不等于原生延后结果。
当前 provider adapters 要求完整 tool-call/output 历史，故使用框架自适应交付；不虚标原生异步支持，
不因连接失败切换协议重放本地副作用。本次不新增 provider-hosted 代码编排入口。

wait 返回有界事件批次，覆盖工具终态、定时器、授权 agent 事件、扩展消息与来源故障。已有事件
立即返回，否则挂起协程；超时不取消任务。消费水位与 wait 的 transcript 结果共同提交，取消或
提交失败不推进水位。GUI 观察与任务查询不消费模型事件。stdout 增量留在输出流，不逐块唤醒；
控制工具不产生自身唤醒。只有明确可合并的进度可覆盖，普通消息和终态不得静默丢弃。

协作来源以目录 revision 作为唤醒信号，从同一 canonical 热历史读取完整 Turn 终态和阶段报告。
监听器持有目标历史租约，关闭事实被收入收件箱后才允许淘汰该目标，避免通知合并或 LRU 丢失终态。
`publish_wait` 以容量变化通知实现可取消背压，不重复调用模型工具。

队列和消息容量由 typed options 限制，满时明确背压；不能通过消费后删除去重信息使迟到重试再次
唤醒。保留去重身份的容量也必须有界，耗尽时拒绝新消息，不撤销已经确认受理的消息。

## 26.4 安全与生命周期

### 完整结果与有界交付

完整结果的保存容量不能由 `wait` 消息大小决定。执行结果、宿主事实与模型投影分层处理：

- 完整结果是会话内不可变记录，包含原始正文、结构化内容、附件、输出文件、技能激活及输出事实。
  身份绑定 taskId 和规范化内容摘要；同身份不同内容属于冲突，不覆盖旧记录。
- 任务状态与唤醒事件只携带有界摘要及完整结果引用。引用包含所属任务、内容摘要和编码字节数，
  不能用可由扩展来源任意提供的文件路径充当内部结果身份。
- 完整结果记录经同一 Thread commit 进入核心 `sessions.sqlite` writer，与终态、交付状态及收件箱
  引用原子落库。使用既有 session entry 存储边界，不新增 Studio 副本、独立 writer 或旁路文件库。
  大结果可拆成带序号和摘要的有界记录；manifest 与全部内容记录必须在同一事务中完整成立。
- 模型默认只接收有界正文、终态及完整结果引用。查询入口需支持会话限定的分段读取，游标绑定任务
  和内容摘要；不能将宿主审计事实混入模型结果。分段读取和 GUI 查看均不消费唤醒收件箱。
  `get_tool_task` 的可选 `resultCursor` 读取一段 UTF-8 编码的结果 JSON 文本；初始游标来自
  `resultReference.cursor`，后续来自 `nextCursor`。每页携带摘要、字节偏移和总长度，不能把单页
  文本误当完整 JSON 对象。游标任务、摘要和 UTF-8 边界不符时明确拒绝。
  显式工具输出预算必须贯穿结果构造链，不能在构造函数中再次套用默认文本预算，导致已校验的
  分页 JSON 或 wait 批次被二次截断。
  批量预算同样不能改写受理回执或已按显式预算构造的结果；这些正文先计入批次占用，剩余预算
  只分配给可压缩的普通结果。模型上下文不足必须在调度或压缩边界处理，不能截断后仍确认原事件。
- 直接交付与 `wait` 采用同一投影边界；附件或结构化内容过大时显式提供完整结果引用，不能静默
  截断成看似完整的结构。引用存在不意味着模型已读取全部内容。
- 恢复先验证 manifest、记录连续性、摘要、任务归属及引用完整性，再发布会话。内容缺失或损坏时
  返回存储错误并保留原始记录，不降级为空成功结果，也不重放工具执行。
- 内存中未保存的完整结果仍由原 owner 持有；只有耐久化水位确认后才允许释放可按引用重读的内容。
  存储失败保留结果与错误供重试，不能把已执行结果替换成超限错误文本。保留内容达到容量边界时
  应限制新任务受理，不能靠清除终态内容或普通消息腾出空间。
  当前 owner 在未保存完整结果累计达到 64 MiB 时拒绝新的普通任务；已经受理的任务仍须保存其真实结果。
  终态任务快照及收件箱只保留模型预览和引用，完整正文由独立不可变记录持有。确认 owner 修订号
  已耐久化后释放正文，后续读取通过核心 repository 校验原摘要；恢复逐条核验内容与预览一致性，
  不将所有结果正文常驻内存。schema 4 显式迁移旧任务及未消费事件，保留任务身份、终态和消费水位。

此迁移必须同时修改任务快照、收件箱、直接交付、查询投影及 SQLite 恢复；仅移除大小检查或把
完整 JSON 塞入现有事件都不满足该契约。存储格式升级由显式迁移处理，不长期保留两条读取路径。

任务审批、互斥和缓存失效属于会话，不随 Turn 切换重置。状态工具经 owner CAS/checkpoint 提交，
不后台修改旧 Turn 的 working-state clone。命令进程统一归任务 owner；write_stdin 仅输入，不轮询。
命令等待 future 由 ManagedCommand 保留；select 的超时或取消只能撤销本次等待，不能丢弃进程
所有权。取消请求发出后必须继续等待同一 future 的真实退出，再提交命令终态。
取消能力与 ManagedCommand 一起返回，backend 不再接收可能陈旧的裸 PID 取消请求；执行 future
持有原物理句柄并处理取消。manager 的独占逻辑租约在最后一个宿主克隆释放时发出取消，不依赖
try_lock 成功，也不持注册表锁调用外部 backend。取消能力本身不代表资源已经释放。
取消先推进原执行 future 的物理终止，再收回 stdin；不能等待被阻塞输入写入占用的 mutex 后才
发送进程取消，否则未读取 stdin 的进程可阻塞归档。活动等待先登记通知再检查状态，避免丢失终态唤醒。
LSP 宿主等直接消费者也必须保留可取消等待的进程 future，终止操作继续驱动实际退出，不能将
发送取消信号作为终止成功。重复观察已完成的进程返回同一真实终态。
缓存实例跨 Turn 存活，但新 Turn 与工作区副作用保守失效已有结果；旧执行的过期 reservation
不能重新填充新 epoch。缓存最多保留 256 条结果，单条成功结果最多 64 KiB，超限只跳过复用。

归档先封闭接收边界，再取消任务、监听器和模型，后台清理保留 closing 与失败信息；所有 sender
克隆同时失效。资源真正释放前不能报告清理完成。有运行任务、监听器或未保存事实的会话不可淘汰。
Closing 保存冻结的清理方式、尚待收束的 Turn 与错误；异步宿主清理持有原 lease，失败不回到 Idle。
显式重试复用 lease；关机重试也必须重新推进已失败的同一清理状态，不能仅返回上次错误。
关机按子会话优先收束，失败时不能清空仍持有资源的 actor registry。
Studio 同样保留原 framework，直到核心关闭及 repository 收束都成功后才移除；失败或调用方取消
不能丢失下一次重试的入口。关闭期间及关闭后不得惰性创建替代 framework，创建仅属于初始化或 Ready。
Studio framework 的资源 owner 与初始化就绪状态分开：初始化失败或等待者取消时保留原 runtime，
下次调用重新完成恢复输入放行；仅就绪实例可用于普通请求。关闭可以取得尚未就绪的原 owner 并禁止再次放行。
宿主 MCP/LSP 观察与启动后台任务保留可重复等待的完成结果；停止时在锁外取消并等待真实退出，
等待者被取消不移走完成句柄。任务 panic 进入关闭错误，不能将发出 abort 当作停止成功。
关闭失败必须跨 FRB/Dart 保留为失败；不得吞掉异常并 dispose bridge。并发关闭共享同次调用，
失败后释放调用缓存以允许显式重试，原 Rust owner 和诊断资源继续保留。
关机进度订阅使用独立拥有型句柄，失败或消费者取消时先取消并等待原生生产者，再取消 Dart 流；
不依赖下一条进度事件来完成取消，重试可在 Failed 状态绑定新的进度订阅。
关闭命令成功回执仅在核心进入 Stopped 后返回；UI 以该回执收束关闭进度。进度流服务中间阶段，
不能要求 bridge 销毁后仍等待最后一条流事件，也不能让迟到的中间阶段覆盖已确认的 Stopped。
持久化接入核心会话存储，任务和收件箱快照随 actor 状态参与同一 checkpoint、提交校验及异步落库，
不在 Studio 产品库另存副本。恢复时校验快照不变量；重启将已保存的非终态任务收束为 interrupted，恢复未消费
消息并重新绑定来源，不重放工具副作用。旧代次事件不得覆盖新运行状态。

### 物理进程所有权

Thread 拥有逻辑任务；独立进程资源宿主仅管理执行句柄、输入输出和子孙进程，不创建另一套会话、
模型等待工具或任务注册表。资源宿主以独占管道租约观察调用方存活，不依赖调用方的析构或进程内监听器。
正常关闭、管道 EOF、帧截断和写回失败都必须先封闭接收，再进入同一资源收束流程。

Linux 每个命令拥有独立监督边界，监督进程承担该命令子孙的收养、终止和回收责任，包括离开原进程组
的子孙；不得只给直接子进程设置 parent-death signal，也不得按可能复用的裸 PID 补杀。Windows 使用
绑定进程树的 Job Object。SSH helper 与本地后端复用同一物理进程协议和监督实现。
Linux 本地 backend 只启动 worker，不保留裸 shell 后备路径；SDK 默认要求 PATH 中安装
pl-remote-helper，也可通过 with_worker_executable 显式提供拥有型可执行资源。Studio 在会话装配时
物化内嵌目标，初始化失败不发布会话；不可变宿主资产可复用，在途 executor 保留自己的资产租约。
非内嵌 Linux 宿主通过 PATH 安装 `pl-remote-helper`，会话装配解析并保留只读 image 租约；
缺失时明确报告安装要求，不恢复裸 shell 后备路径。CI 的 Linux server 门禁安装同一生产 worker。
本地内嵌程序以匿名 inode 的只读 fd 保留，通过 procfs fd 路径执行；不将可执行临时文件留给
析构函数删除，避免 GUI 异常退出遗留目录项。执行前关闭所有可写 image fd。
注入 command backend 时替代默认 command 安装，不重复注册 exec/write_stdin。
只有进程树及输出任务均退出后才报告执行终态；收束失败保留资源 owner 和错误，不能清空登记后返回成功。
SSH wire 写端由一个有界队列和唯一写协程串行拥有，不持注册表或共享 writer 锁执行 IO。
SSH 客户端断连是可持续观察的单向状态，不是一次性通知；先到和后到的等待者均立即观察已断连。
请求登记在 pending 队列的同一同步边界内重新检查断连状态，关闭后的请求不能越过排空边界成为孤立等待者。
客户端在入队前校验完整帧，发送方取消不撤销已受理帧；唯一写任务写完当前帧或关闭整个字节流。
在途请求与发送队列均有界，容量不足明确报告背压。客户端保留读写任务的完成句柄，显式关闭等待
两者退出；最后一个客户端租约释放时发出关闭信号，后台读写任务不能自行延长客户端租约。
SSH manager 关闭先原子封闭连接受理并停止重连意图，等待已受理连接与观察任务收束，再关闭各传输并
等待 SSH 子进程退出。失败保留原连接记录供重试；Studio 在依赖远端的 MCP/LSP 停止后关闭 manager。
写失败通知接收循环进入关闭；关闭撤销当前写帧后丢弃连接，不在同一字节流续写半帧。
SSH 物理 registry 串行受理有界资源请求，受理后拥有启动和 IO future；RPC 取消只撤销回执等待。
关闭先封闭 registry 接收，再取消并等待其资源任务集合，不通过清空登记来制造清理完成。
业务退出、输出保存失败和监督器失败在远端终态中分别保留，不能把 IO 失败编码为成功退出。
Linux worker 在启动业务程序前建立 subreaper、pidfd 与 SIGCHLD 观察能力，业务 stdin/stdout/stderr
与控制 socket 分开继承。控制描述符不传给业务子进程；控制 EOF、取消请求和终止信号进入同一
收束状态。先 TERM，宽限期后 KILL，继续收养并回收脱离进程组的后代；同一 worker 独占 waitpid，
只为尚未回收的直属子进程取得 pidfd，禁止将 procfs 读取的裸 PID 用于事后补杀。
控制通道返回类型化启动、清理错误及退出事实；调用方必须并发读取控制事件和业务输出。
业务进程启动前先返回带版本的 Ready；宿主校验后显式发送 Start，版本不匹配或初始化探测结束
只能关闭租约，不能执行命令。Start 前取消返回 StoppedBeforeStart，不能伪造成功执行结果。
业务程序创建失败单独返回 StartFailed 与原始系统错误，不伪造空的 Exited，也不要求宿主解析 stderr。
宿主客户端持有唯一租约，控制器和事件读取器的克隆不延长该租约；释放租约关闭 socket 写方向，
避免读任务持有 fd 导致 worker 永远等不到 EOF。业务程序、参数和 cwd/env 在 Ready 版本校验后，
通过私有控制 socket 的有界长度帧传递，配置完整解析后才接收 Start。worker argv 仅含模式和控制 fd；
配置只作用于业务进程，不覆盖监督器的装载环境，也不把环境值放进监督器 argv 或诊断输出。
宿主并发读取有界控制帧与 worker 退出，只有真实退出和终态
帧一致才交付结果；清理错误可独立订阅，不能为了返回错误而提前丢弃仍活着的 worker。
关闭后的控制描述符从等待集合移除，避免 HUP 持续就绪造成忙循环。worker 本身不是 Thread/Turn owner。
