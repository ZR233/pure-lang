# 26 - Thread 工具任务与统一唤醒

## 所有权与注册

Thread owner 串行拥有任务、交付与消息状态，工具实例以 Registration 转移给 Thread。
Studio 统一装配 root/child/恢复的工具和物理服务，不在每轮重建命令管理器或保存另一份 registry。
动态目录变更与 executor 重连保持已冻结租约；关闭逐个等待实例，失败保留进度重试。

## 执行与交付

任务先提交 Running 事实再执行。普通工具默认一秒交付窗口，窗口内完成提交实际结果，
超时提交原调用关联的任务回执，执行 future 留在 Thread。后台完成将结果、任务终态与
消息一次提交；模型在后续请求准入时消费。已受理任务可跨 Turn 运行，终态不得重复交付。

完整业务 payload、观察结果、实际 delivered_context 和任务终态分别保存。失败可携带
已观察输出；取消后迟到结果仍保留，但不应用其扩展、交互或结束控制。实际模型历史使用
已保存 delivered_context，不能用当前渲染器重新解释旧业务正文。

具有控制权限的工具独占批次并保持前台执行。工具等待只报告就绪，完整后台结果由模型准入
统一消费，避免 wait 与收件箱重复交付。任务查询不消费消息；任务取消只提交意图并请求
执行 token 取消，直到执行与物理清理返回才产生终态，不把 Requested 当成完成。

消息以稳定 ID 幂等受理，来源和上下文不能冒充 system 或审批。消费水位与模型请求准入
同 commit，准备失败或准入前取消不消费。明确输入、后台消息与 UI 观察有各自语义，
消息到达不隐式创建有费用的模型尝试。

## 完整结果与资源

执行完成而提交失败时，owner 保留原始完成对象与执行租约，暂停新模型准入；提交重试
不再次执行工具。完整载荷与上下文同日志保存，不按工具类型建表。大型二进制或输出文件
使用带摘要和长度的稳定资源引用；单页预览、临时路径或尚未归档的 capture 不等于完整资源。

exec/write_stdin 共享 Thread 私有进程管理器，任务身份校验先于内部进程映射。输出必须排空
后才归档，远程归档使用真实远程范围读取；失败保留源 capture，不重演命令。物理权限和
工作区限制由工具后端执行，core 不根据工具名或参数路径猜测授权。

## 生命周期与验证

停止、关闭与任务取消由 owner 核对执行代次。关闭先禁止新工作，取消在途执行并等待物理
结束，重试未提交结果，再关闭工具与模型并 flush 最终日志。关闭失败保留 owner；冷恢复
把遗留 Running 收束为 Interrupted，不恢复旧 executor 或自动重放副作用。

回归覆盖窗口内/后台交付、消息幂等与消费、取消及迟到结果、目录撤销、结果提交失败重试、
共享服务租约、资源归档、真实进程回收、冷恢复和原始正文重放。core 测试只依赖抽象端口，
真实 provider/tool/Studio 装配在对应消费者验证。详见 [27](./27-core-boundaries-and-replay.md)。
