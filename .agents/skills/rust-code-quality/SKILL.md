# Rust 代码质量

## 工作流

1. 先读取仓库根目录 `AGENTS.md` 及改动范围内更具体的说明，理解调用链、所有权、失败路径和验证入口。
2. 质量重构时把用户指出的例子提炼成可搜索的异味，在约定范围及直接相邻边界盘点同类问题；统一处理同一原因的问题，并明确保留例外，不只修改被评论的单个位置。
3. 完整阅读 [实现与表达](references/implementation.md)。
4. 涉及运行时失败、错误传播、缺陷修复、测试新增或验证证据时，再完整阅读 [错误与验证](references/errors-and-validation.md)。
5. 识别相邻专项：
   - 公共或跨 crate 接口、类型、错误、模块、依赖或宏边界：`rust-api-design`；
   - 锁、原子、异步执行、任务、回调或共享状态：`rust-concurrency-safety`；
   - `unsafe`、FFI、裸指针、手工布局或手工 `Send`/`Sync`：`rust-unsafe-safety`；
   - 测试策略、层级、缺陷敏感度或低价值测试审计：`test-quality`。
6. 修改后执行与风险匹配的定向测试，再按 `AGENTS.md` 执行适用的仓库门禁；不得用 `allow`、弱化断言、静默跳过或无界重试制造通过结果。

## 基线

- 让核心类型、公共入口和编排步骤先出现，边界 helper 和底层细节靠后；`#[cfg(test)] mod tests` 保持为最后一个 item。
- 让函数、文件和模块围绕一个状态转换、领域规则或变化原因组织；简单职责使用单文件，只有存在多个真实子职责时才引入目录模块，不创建空壳转发层。
- 让类型和名称表达单位、所有权、状态与业务意图；使用 enum、newtype、options struct 或领域对象消除含糊布尔值和非法状态。
- 让已知 schema 的 JSON、TOML、YAML 和协议消息使用 typed struct/enum、serde 或现有协议类型；只在确实开放或异构的边界保留动态值。
- 让可恢复失败沿调用链返回具体错误，并保留操作、关键上下文与 source；日志不能代替错误传播。
- 让资源取得、发布、回滚和释放责任清楚；避免无必要的 clone、共享可变状态和全局缓存。
- 让注释解释不变量、安全契约、协议要求或取舍，不复述语句；公共 API 按项目规范补齐 rustdoc。
- 让修复附带能稳定触发根因的回归测试，并验证可观察后置条件，而不只验证进程成功退出。

## 交付

总结实际执行的格式化、静态检查和测试，明确未执行项及原因。交付前检查 `git diff --check`，确认没有意外生成文件或范围外改动。
