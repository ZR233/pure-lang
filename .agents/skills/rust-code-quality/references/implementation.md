# Rust 实现与表达

## 1. 代码组织

让维护者从入口快速看出主要流程，再逐步进入细节。文件顶部先放核心类型、公共入口与主要编排，辅助函数和底层边界随后出现；不要为了机械排序打散紧密协作的状态机或协议步骤。

### 1.1 单一职责

让函数完成一次状态转换、验证步骤、数据转换或边界操作。解析、校验、持久化、发布和回滚具有不同前置条件或失败策略时，拆成具名阶段。长函数真正需要拆分的信号是混合多个抽象层、拥有多套错误策略、反复切换状态或无法单独验证。

让模块聚焦一个领域不变量，并按变化原因拆分。单一职责且不拥有子模块时使用 `foo.rs`；只有已经存在多个真实、内聚的子职责时，才使用 `foo/mod.rs` + `foo/child.rs`。`lib.rs` 与确有子模块的 `mod.rs` 只承担目录页职责：说明边界、声明子模块并导出自然入口。禁止只有 `mod.rs` 的目录，也不要让 `mod.rs` 只转发唯一子文件。

多个同前缀文件共同维护一个边界时，先判断它们是否应成为父模块下按目的命名的子职责，而不是继续堆叠平铺前缀。反过来，不要只为缩短文件名或追求对称创建目录。生产模块接近 500 行时主动检查职责，超过约 800 行时拆分，或说明保持整体的单一职责依据。

结构迁移完成后删除旧文件、空目录、转发别名和只为旧测试存在的 helper，并搜索旧模块名与旧路径确认调用方已经完整迁移。没有明确跨版本兼容责任时，不保留新旧结构双轨入口。

### 1.2 修改与副作用

通过 `&mut`、返回值、类型化状态转换或名称清楚的方法显式表达修改。超过三个参数时优先考虑 options struct、builder 或领域对象；禁止语义不清的 `bool` 和 `Option<bool>` 参数。

读取函数不要暗中持久化、登记、启动任务或吞掉错误。多阶段操作要明确已发布状态、待回滚资源、重试语义和最终所有者。能够由所有权与析构表达时使用 RAII。

### 1.3 结构化数据

已知 schema 的 JSON、TOML、YAML、配置和协议消息优先使用 typed struct/enum、serde 或现有协议库类型，不手写字段拼装、字符串协议或层层 `Value` 索引。typed 边界应覆盖输入校验、字段命名、默认值和序列化，而不是只在最外层包一层后立即退回动态访问。

只有扩展字段、透传载荷或返回形态确实开放/异构时才保留动态值，并把范围限制在 adapter 或 wire 边界；一旦进入具有稳定语义的领域逻辑就转换为明确类型。不要为了形式统一给真正开放的映射制造没有约束力的 DTO。

## 2. 命名与领域词汇

使用仓库已有领域词汇表达业务意图、单位和所有权，不以容器形状或临时实现命名。已知更准确概念时避免 `data`、`info`、`manager`、`handler` 等泛化名称；集合名称说明集合角色，布尔名称能直接读出真假含义。

同一概念在类型、字段、函数、日志和文档中使用同一词。只有旧名称确实表达错误时才沿完整调用链一致迁移，不保留含义相同的双重入口。

## 3. 函数与控制流

保持正常路径清楚，让边界检查与错误返回靠近依据。优先提前返回减少嵌套，但不要把协议步骤或回滚压缩成难以审计的链式表达。

除非确需所有权，参数优先借用。使用返回值、元组、结构体或迭代器代替输出参数。返回类型应让调用方区分成功、暂不可用、不支持和真实失败，不能把决策状态折叠成布尔值或日志文本。

迭代器与闭包适合纯转换和局部筛选；状态机、资源回滚与副作用编排更适合显式控制流。热路径避免无必要的分配、克隆、格式化与临时集合。

检查零长度、空集合、最大值、溢出、对齐、包含与半开区间、部分完成和重复调用。计算大小、索引与时间时优先使用受检算术，并在错误中保留失败原因。

## 4. 注释与文档

注释解释代码无法表达的不变量、安全契约、协议步骤、并发顺序或取舍，不复述语句。临时限制说明触发条件和可观察后果；有可追踪事项时附链接，不写无上下文 `TODO`。

公共类型与函数说明调用方关心的所有权、失败条件、阻塞性、并发保证、状态变化和兼容性。公共 API 提供适用的 `# Errors`、`# Panics`、`# Safety`，示例优先使用 `?`。

## 5. 常见异味

看到下列现象时回到所有权和边界重新判断：

- 同一协议常量、错误映射或状态判断在多处复制；
- 调用方穿透多层内部对象才能完成领域操作；
- 新增只服务一个调用点且没有独立不变量的抽象；
- 为绕过类型或生命周期约束进行无依据 clone、泄漏或全局缓存；
- 用字符串传递结构化状态，或用日志代替错误返回；
- 静默采用猜测的默认值或后备路径；
- 一个修复混入无关重命名、格式改写或大范围重构。

删除重复知识不等于机械合并相似代码。抽象必须让不变量更集中、调用点更容易审计；隐藏关键控制流时保留局部显式实现。
