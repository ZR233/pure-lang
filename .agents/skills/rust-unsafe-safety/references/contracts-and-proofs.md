# Rust unsafe 契约与证明

## 1. 缩小边界

先在安全代码中验证长度、范围、对齐、状态和所有权，再进入最小 `unsafe` 块。不要把整个函数或模块包入 unsafe，也不要通过扩大 `unsafe fn` 把实现责任转嫁给调用方。

每个块的注释独立回答本操作的前置条件为什么成立。共享条件可以在安全包装器文档中集中说明，但块内仍指出依赖哪一项。

## 2. 指针有效性

证明非空要求、对齐、指向有效 allocation、访问范围位于同一 allocation、对象已初始化，并在访问期间不会释放或重新分配。整数转指针还要证明地址 provenance 与映射有效，不能只检查数值范围。

构造 slice 时检查元素数与字节长度的乘法溢出、零长度指针规则和整个范围。读取结构体前验证长度、对齐、有效位模式和 padding；不可信字节不得直接转成任意 Rust 类型。

## 3. 别名与可变性

创建 `&mut T` 要在整个借用期内独占对应内存。外部线程、C/C++、Dart、系统 API 或回调可能并发访问时，不能轻易建立普通可变引用；使用原始指针或拥有明确共享内存契约的抽象表达真实语义。

从共享引用取得可变访问必须通过 `UnsafeCell` 或已证明的内部可变性类型。不能通过指针转换绕过 Rust aliasing 规则，也不能以“实际运行正常”证明没有未定义行为。

## 4. 生命周期与析构

返回引用或保存裸指针时，证明来源对象至少存活同样久。延长局部引用生命周期、保存可移动容器元素地址或锁释放后使用内部指针，都需要稳定所有权机制。

手工分配、数组构造和外部登记记录已初始化部分，失败或 panic 时只析构已初始化元素。`ManuallyDrop`、`MaybeUninit` 与原始 allocation 不得产生重复析构、读取未初始化内存或泄漏。

所有权交给外部系统或另一执行上下文后，原对象停止释放；取回所有权需要唯一完成令牌或状态转换。引用计数不替代完成、取消或注销协议。

## 5. 手工线程安全

`unsafe impl Send` 证明值可以在线程间转移，`unsafe impl Sync` 证明共享引用可并发访问。逐字段检查裸指针、外部 handle、线程局部状态、锁与回调，说明同步原语保护哪些字段，以及析构是否可能与操作重叠。

需要原子内存顺序、锁或取消证明时同时使用 `rust-concurrency-safety`。

## 6. 布局与转换

只有 FFI、持久化二进制或 wire 确实要求时使用 `repr(C)`、整数表示或 packed 布局，并记录字段顺序、大小、对齐、字节序和 padding。避免读取、比较或复制未初始化 padding。

`transmute` 要证明源与目标的大小、对齐、有效位模式、生命周期与所有权完全兼容。优先显式字段转换、受检整数转换、字节转换函数或专用构造器。
