# FFI 与外部边界

## 1. ABI 与声明

让外部函数声明与真实 ABI、参数宽度、符号、可变参数和返回语义一致。使用固定宽度 FFI-safe 类型；Rust enum、trait object、slice、`String` 和未声明布局的 struct 不直接跨 ABI。

进入 Rust 前验证外部指针、长度、枚举值、UTF-8 与回调上下文；离开 Rust 时转换为对方约定的所有权和错误形式。任何 panic 都不得穿越不支持 unwind 的边界；在边界捕获时仍要保证资源与状态一致。

## 2. 字符串与缓冲区

C 字符串要证明 NUL 终止、有效范围和使用期间生命周期；需要 UTF-8 时显式验证。外部提供的 pointer/length 组合检查空指针规则、受检长度计算、可读写权限和整个范围，不把临时 buffer 的引用保存到调用结束后。

Rust 分配的内存只能由匹配的 Rust 释放入口回收，外部分配同理。跨边界传递容量、长度和指针时把三者视为单一所有权契约，禁止用错误 allocator、错误 layout 或重复释放。

## 3. 回调与上下文

回调函数指针与 context pointer 作为一个能力对象管理。context 需要稳定所有者、线程安全契约和注销协议；注销先阻止新回调并等待在途回调结束，再释放对象。

不能假定外部框架在 unregister 返回时已经同步完成，除非文档明确保证。回调说明调用线程、可重入性、允许阻塞与否、panic 处理和 context 保留时长。

## 4. Flutter Rust Bridge 与生成边界

不得手工修改生成的 FRB 文件。修改生成输入后使用仓库唯一生成入口，并分开审查生成 diff 与手写 unsafe 边界。

Rust protocol、FRB DTO 与 Dart model 保持 typed 转换，不通过 raw JSON 或不受检整数绕过生成层。外部对象引用、stream sink、Dart isolate 交互和 library handle 的线程/关闭语义必须按实际生成 API 与平台契约证明。

## 5. 系统 API 与资源句柄

文件描述符、动态库、Windows handle、进程与 Job Object 等资源使用专用拥有类型包装。明确无效 sentinel、复制/继承语义、关闭函数、关闭线程限制和失败后的所有权。

系统调用返回值先按平台契约判断成功与错误，再构造安全值。句柄关闭与并发操作重叠时使用明确的生命周期和同步协议；超时或子进程退出不自动证明所有外部资源已停止访问。

## 6. 验证

覆盖空值、零长度、最大长度、非 UTF-8、未知枚举、错误 ABI 返回、重复注销、回调与关闭竞争、部分初始化和释放失败。能使用 Miri、sanitizer 或平台检查工具时作为补充，但结论仍以可审查契约和完整释放链为准。
