# Rust 公共接口设计

公共接口不仅是 `pub`，还包括跨组件约定、配置格式、工具输入输出和测试运行器输入。在 Pure-Lang 中，provider 协议、FRB DTO、Dart model 和持久化格式也属于共享契约。

## 设计顺序

1. 读取[项目约束](../../../AGENTS.md)，确定调用方、契约所有者、有效状态、失败语义和兼容责任。架构或协议变化按项目约定先同步设计。
2. 完整阅读[类型与接口](references/types-and-interfaces.md)。
3. 涉及模块、可见性、依赖、feature 或宏时，完整阅读[模块与依赖](references/modules-and-dependencies.md)。
4. 优先扩展已有边界，迁移受影响消费者；不并行创建第二套登记表、错误体系或配置来源。

允许有意采用语义合适的公共依赖类型，并精确重导出、承担兼容责任；内部实现依赖继续隔离。这不改变 `pl-core` 的产品无关性和项目规定的禁止依赖。

跨执行上下文的接口同时使用 `rust-concurrency-safety`；要求调用方维护内存安全前置条件的接口同时使用 `rust-unsafe-safety`。接口验证按 `test-quality` 选择完整行为边界。

## 验收

调用方无需穿透内部结构、猜测状态或解析诊断文本即可完成领域操作。所有权、取消、失败、释放、类型身份与兼容保证可从接口判断；受影响消费者、协议映射和设计保持一致。
