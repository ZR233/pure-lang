# Rust 类型与接口

## 1. 用类型表达不变量

地址、标识符、单位、权限、状态、代次和协议字段具有不同语义时，使用 newtype、enum、位标志或经过校验的结构，不使用裸整数、字符串和关系松散的参数。

解析或校验完成后返回已验证类型，避免调用点重复检查。状态转换具有顺序约束时，使用不同状态类型、操作 enum 或只能由合法前态调用的方法。多个布尔字段形成组合状态时改成 enum；多个布尔参数控制行为时改成 options struct 或具名入口。

配置与 wire DTO 可以公开纯数据字段；拥有资源、锁、持久化状态或复杂不变量的类型保持表示私有，公开表达领域意图的方法。不可变配置、已验证输入、可变运行时状态、持久化模型与 adapter DTO 的生命周期和变化原因不同时，使用独立类型。

## 2. 设计能力边界

让 trait 表达小型能力集合，而不是继承层次。只暴露使用方需要的操作；可选行为使用扩展 trait、adapter 类型或 feature，不持续扩大中央 trait。

优先通过 provider、store、runtime、registry、adapter 等具名部件组合服务。静态组合使用具体字段或泛型；只有运行期确实需要异构实现、插件或对象安全边界时使用 trait object。

不要强迫调用方穿透多层内部对象。转发方法只有在保护封装、补充校验或表达领域动作时才有价值。调用方只需快照、迭代或查询时，提供边界明确的结果；热路径不要为方便分配完整快照。

## 3. 明确所有权与异步语义

接口明确谁创建、登记、发布、借用、取消和释放资源。跨线程、进程或 provider 边界传递时，使用所有权类型、能力句柄、代际标识符或 RAII guard 防止重复释放、陈旧句柄和部分发布。

异步 API 说明取消、超时、后台任务、阻塞性和最终结果归属。返回 future 的 trait 方法显式保证 `Send`；不要通过宏隐藏生命周期和线程安全约束。流式 API 说明终止事件、错误传播、背压和调用方提前停止后的清理责任。

## 4. 把错误作为接口

调用方需要匹配、转换、重试或回滚时，返回类型化 enum 并保留 source；不暴露 `String` 或 `anyhow::Error`。领域 crate 拥有自己的错误类型，第三方错误在边界转换，不能迫使所有调用方依赖具体实现。

新增错误变体时检查所有穷尽匹配、wire 映射、用户显示和兼容策略。不要为了避免修改调用方而把新错误折叠成既有宽泛错误。协议 enum 和状态机保持穷尽匹配，不用 `_` 静默吞掉未来变体。

## 5. 处理兼容性

兼容性包括 Rust 源码、feature、错误匹配、配置、serde 字段、FRB/wire、持久化布局和运行时行为。即使尚未发布，也要在同一改动中迁移 workspace 调用方，避免半迁移状态。

只有明确存在跨版本兼容责任时才保留 adapter、别名或兼容解析。适配层要有单一所有者、清楚停止条件和测试；不要永久保留重复注册表、双份 DTO 或静默回退来掩盖迁移缺口。
