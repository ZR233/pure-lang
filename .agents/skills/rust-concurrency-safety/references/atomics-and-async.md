# Rust 原子与异步

## 1. 原子状态

为每个原子变量写清它承载的含义：纯计数、状态发布、所有权转移、代次标识还是唤醒合并。多个原子共同表达一个不变量时，说明它们如何保持一致；无法独立证明时使用锁或单一状态对象。

### 1.1 内存顺序

使用 Acquire、Release 或 AcqRel 时明确发布者写入的数据和观察者读取的数据。发布操作前完成受保护写入，获取操作确认状态后再读取。

`Relaxed` 只用于不承担同步作用的统计计数，或已经由另一条明确同步边保护的状态，并说明真实同步路径。`SeqCst` 只在确有全局排序要求时使用；增强内存顺序不能修复丢失唤醒、复合状态撕裂或生命周期错误。

比较交换循环处理失败返回的新值，明确弱比较交换的重试条件，避免无界自旋。计数减到零触发释放时防止下溢、重复释放和从零复活；代次标识考虑回绕与复用。

## 2. 异步执行

把每个 `.await` 视为潜在并发和取消边界。挂起前确认没有持有同步锁、不可跨挂起 guard、裸借用或要求当前线程保持不变的状态。

异步运行时线程不直接执行无界阻塞 I/O、长时间计算或同步等待。使用项目已有的阻塞隔离边界，并定义关闭与取消。派生任务必须有所有者：等待句柄、纳入任务组、保留可观察 handle，或明确且受控的后台生命周期。

### 2.1 取消安全

每个挂起点都可能取消。部分写入、已取出队列项、已登记 waiter、临时文件和临时取得的能力必须保持一致或由 guard 回滚。无法取消安全的操作使用显式不可中断阶段或持久化状态机表达。

超时包装不能让内部任务在后台继续修改调用方已视为失败的对象。若保留后台工作，返回可观察句柄并定义最终结果、资源与错误的所有者。

### 2.2 stream 与背压

说明 producer 停止、consumer 提前退出、channel 关闭和终态错误的语义。避免无界 channel 掩盖背压；缓存要有容量、丢弃或阻塞策略。终止事件只能发布一次，错误不能在中间层被日志吞掉后转换为正常结束。

## 3. 审查证据

至少追踪一条完整发布/观察链、一条取消或错误链和对象最终释放。测试验证状态与后置条件；超时只防止测试永久挂起，不作为成功判据。压力、loom 或其他模型检查可以补充证据，但不能替代具体同步证明。
