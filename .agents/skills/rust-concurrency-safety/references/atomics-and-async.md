# Rust 原子与异步

## 1. 原子状态

为每个原子变量写清它承载的含义：纯计数、状态发布、所有权转移、代次标识还是唤醒合并。多个原子共同表达一个不变量时，说明它们如何保持一致；无法独立证明时使用锁或单一状态对象。

### 1.1 内存顺序

使用 Acquire、Release 或 AcqRel 时明确发布者写入的数据和观察者读取的数据。发布操作前完成受保护写入，获取操作确认状态后再读取。

`Relaxed` 提供原子性和该原子对象的修改顺序，但不发布其他内存访问。只需这些保证时可以使用，例如统计计数或正确处理回绕与复用的编号分配；其他数据已有独立同步边时也可使用。说明为何无需发布其他数据，或指出实际同步路径；不能从编号已分配推导对象已可见，也不能用当前架构的行为代替 Rust 内存模型证明。`SeqCst` 只在确有全局排序要求时使用；增强内存顺序不能修复丢失唤醒、复合状态撕裂或生命周期错误。

比较交换循环处理失败返回的新值，明确弱比较交换的重试条件，避免无界自旋。位图或标志更新说明各位是否独立，清除操作不能覆盖并发发布的新状态。计数减到零触发释放时防止下溢、重复释放和从零复活；代次标识考虑回绕与复用。

## 2. 异步执行

把每个 `.await` 视为潜在并发和取消边界。挂起前确认没有持有同步锁、不可跨挂起 guard，或其他生命周期／线程要求与挂起冲突的状态；普通合法借用本身不是禁止条件。异步锁是否跨 `.await` 由其契约决定，必须说明保护的不变量、持锁操作、重入与锁顺序、取消及关闭路径，不能仅因 guard 可挂起就认为安全。

异步运行时线程不直接执行无界阻塞 I/O、长时间计算或同步等待。使用项目已有的阻塞隔离边界，并定义关闭与取消。派生任务必须有所有者：等待句柄、纳入任务组、保留可观察 handle，或明确且受控的后台生命周期。

### 2.1 取消安全

每个挂起点都可能取消。部分写入、已取出队列项、已登记 waiter、临时文件和临时取得的能力必须保持一致或由 guard 回滚。无法取消安全的操作使用显式不可中断阶段或持久化状态机表达。

超时包装不能让内部任务在后台继续修改调用方已视为失败的对象。若保留后台工作，返回可观察句柄并定义最终结果、资源与错误的所有者。

### 2.2 stream 与背压

说明 producer 停止、consumer 提前退出、channel 关闭和终态错误的语义。避免无界 channel 掩盖背压；缓存要有容量、丢弃或阻塞策略。终止事件只能发布一次，错误不能在中间层被日志吞掉后转换为正常结束。

## 3. 审查证据

至少追踪一条完整发布/观察链、一条取消或错误链和对象最终释放。测试按 [test-quality](../../test-quality/SKILL.md) 复用或增强完整行为证明，不按线程数或循环次数机械新增。验证状态与后置条件；超时只防止测试永久挂起，不作为成功判据。压力、loom 或其他模型检查可以补充证据，但不能替代具体同步证明。
