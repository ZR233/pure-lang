# Rust 并发安全

## 工作流

1. 列出共享对象、所有者、全部读写执行上下文、状态转换和最终释放责任。
2. 涉及锁、等待、回调、关闭或资源生命周期时，完整阅读 [锁与生命周期](references/locking-and-lifecycle.md)。
3. 涉及原子操作、内存顺序、无锁状态、异步执行、超时或取消时，完整阅读 [原子与异步](references/atomics-and-async.md)。
4. 优先依次考虑：不共享、消息传递所有权、共享不可变值、保护明确不变量的锁、能够独立证明的原子状态，最后才是需要手工健全性证明的共享内存。
5. 构造具体交错，验证发布、观察、取消、失败与释放链；不要只以“可能竞争”或“压力测试未失败”作为结论。

## 分析基线

- 说明每个状态由谁写入、谁观察、依靠哪条同步边建立先后关系。
- 说明等待条件、唤醒协议、虚假唤醒、丢失唤醒与重复完成如何处理。
- 让锁作用域短，且不持锁执行 I/O、`.await`、长计算、进程操作或未知外部回调。
- 让派生任务、stream、Driver/DTD/GUI 子进程和后台工作都有明确所有者、关闭协议与错误传播路径。
- 让超时不遗留仍会修改状态的后台工作；确需继续时返回可观察句柄并定义最终结果归属。
- 检查公共类型及其全部字段是否真正满足 `Send`/`Sync`，不因外层存在 `Arc` 就假定内部并发安全。
- 涉及 `unsafe impl Send/Sync`、裸指针或 FFI 回调时，同时使用 `rust-unsafe-safety`。

## 验收

实现与审查结果必须能回答：每个共享状态的同步边是什么，等待如何结束，取消与失败如何回滚，关闭如何阻止新工作并等待在途工作，是否存在死锁、丢失唤醒、重复完成、陈旧标识符或释放后访问。测试优先确定性控制关键交错，压力测试只补充置信度。
